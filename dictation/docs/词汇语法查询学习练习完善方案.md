## 1. 结论与交付目标

建议在现有 Python 本地服务、SQLite、原生 JavaScript 页面上增量完善，保留现有精听、真题和个人中心。词汇与语法继续共享条目身份、个人资产、学习计划和复习调度，同时分别提供适合各自的详情页和练习题型。

最终形成可连续使用的流程：

**查询词语或语法 → 阅读讲解与例句 → 加入学习计划 → 主动回忆或实际作答 → 查看解析 → 错题复练 → 按期复习 → 查看进度。**

当前问题有三层，必须一起解决：

1. **内容不足**：本地没有单词包和词典，现有语法包大量缺少中文释义。
2. **交互不完整**：查询、条目详情、计划、翻卡之间缺少直接衔接，尚无完整的客观练习流程。
3. **状态存在缺陷**：已复习卡重复进入当天队列，内容更新覆盖个人笔记，以及部分接口绕过内容质量限制。

本方案中的“功能完整”指词汇和语法都能够完成上述流程，并有真实内容通过验收；不把支持 N1–N5 筛选等同于已经具备完整的 N1–N5 教材库。先修复现有 N2 语法内容，建设首个可用词汇包，再逐步增加其他等级的内容。

本次仅新增本文档。原工作区已有大量改动，分析过程中未修改业务代码、教材正文或用户学习数据库。

## 3. 产品结构与使用流程

### 3.1 工作区组织

保留 `/lexicon` 入口，调整为五个功能入口；“词汇 / 语法 / 全部”作为跨页面筛选，详情和练习按类型呈现。

| 入口 | 内容与主要动作 |
|---|---|
| 查询与词库 | 统一搜索、词汇/语法筛选、等级和教材筛选、内容包与单元浏览 |
| 今日学习 | 到期复习、今日新条目、继续未完成任务、预估卡数 |

条目详情包含两个共用动作区：学习动作（加入计划、收藏、立即练习）和个人资料（笔记、标签、来源跳转）。词汇突出表记、读音、词性、多义项、搭配；语法突出接续、用法、语气、限制和近义辨析。

### 3.3 两条核心流程

```mermaid
flowchart LR
    A[查询 / 教材浏览 / 精听划词] --> B[词汇或语法详情]
    B --> C[加入计划与今日学习]
    B --> D[立即专项练习]
    C --> E[回忆与作答]
    D --> E
    E --> F[答案、解析与个人笔记]
    F --> G[错题重练与长期复习]
    G --> H[学习记录与薄弱项]
    H --> C
```

词汇示例：在句子里选中活用形 → 显示可能原形及变换说明 → 确认具体义项 → 保存句子来源 → 学习读音与含义 → 输入假名或选择释义 → 错题复练。

语法示例：搜索中文意思或文型 → 阅读接续、场景、限制及例句 → 比较相近文型 → 完成接续/填空/辨析练习 → 查看各选项原因 → 将薄弱方向加入复习。

## 4. 查询功能方案

### 4.1 统一查询范围

搜索范围包含已安装内容包、已安装词典、个人收藏/笔记；界面显示实际可用来源。正文命中、读音命中、例句命中分别标识，用户能看出结果为何出现。

| 能力 | 具体行为 |
|---|---|
| 单词查询 | 汉字、假名、片假名、罗马字、中文/英文释义；支持原形与经词典确认的活用候选 |
| 语法查询 | 文型、异写、中文释义、接续条件、语义标签和例句；完整句子返回候选，不能把子串匹配宣称为完整句法分析 |
| 筛选 | word / grammar、JLPT 等级或未分级、内容包、单元、词性/语义分类、已收藏、学习状态 |
| 排序 | 表记精确 > 读音精确 > 前缀 > 词典验证的原形候选 > 释义/例句包含；常用标记和变换代价作次级排序 |
| 列表 | 高亮命中片段、读音、简释、来源和学习状态；分页及总数/更多结果提示 |
| 辅助 | 最近搜索、清空历史、搜索建议；日文输入法组合阶段不触发查询 |
| 无结果 | 展示覆盖范围、筛选限制、词典安装状态；允许添加个人词条，不编造解释 |

搜索标准化只作用于索引和比较值，原文和稳定 ID 不变。分层处理 Unicode NFKC、波浪号异写、读音的平片假名归一；保留长音、促音、浊音等有意义差异。罗马字转换保留原始输入并提供候选，处理 `n`、长音和常见输入方式，不把转换结果视作唯一读法。

跨包同形词显示为可展开的来源组，不自动合并语法条目或不同义项。词典同一词目的多表记、多读音和义项限制必须保留，不能将任意读音与任意义项组合。

### 4.2 词典与索引

按项目原有选型新增 `dictionary_build.py`、`dictionary_store.py` 和 `jp_inflection.py`，使用本地 JMdict 数据构建 SQLite 词典。JMdict 是以日语为中心的多语词典，官方同时提供日英子集；首期按现有 ADR 导入日英内容。中文释义由本地教材或独立审核的内容补充，不假定词典自带完整中文。[JMdict 项目说明](https://www.edrdg.org/jmdict/j_jmdict.html)

实施规则：

1. 词典放在独立 SQLite 文件；个人学习状态仍在 `learning.sqlite3`。索引可重建，用户资料不可随重建删除。
2. 保存数据来源、版本、下载日期、哈希、导入语言、许可及署名；提供更新检查和失败回滚。按官方适用说明保留署名和 CC BY-SA 4.0 信息，其他语言资料单独核对，沿用既有教材私有包边界。[EDRDG 许可说明](https://www.edrdg.org/edrdg/licence.html)
3. 表记和读音走索引精确/前缀查询；释义和例句使用全文/子串索引。内容包按 revision 构建索引，避免每次查询重复读盘审计全部包。
4. 探测 FTS5 和 trigram 能力。不能将默认 tokenizer 当作日语分词器；trigram 不覆盖的短查询走专用短词索引或有界包含查询；缺扩展时仍能精确和前缀查询。具体降级在 UI 中说明。[SQLite FTS5 文档](https://www.sqlite.org/fts5.html)
5. 查询参数长度、分页大小和去活用候选数有上限；SQL 参数化，FTS 运算符和 LIKE 通配符按字面查询处理。
6. 去活用先支持常用动词、形容词变化及多步组合；带词性约束、深度限制和候选去重。所有候选需查回词典，多解并列显示，附原输入和变换链。
7. 未安装词典时照常查询内容包与个人卡片；提供安装/导入入口，不把首次词典下载作为每次打开学习页面的前置步骤。

KANJIDIC2、详细汉字字源和笔顺不阻塞本次词汇语法闭环，可后续扩展。首期发音使用可用的日语语音或已有音频，不把 TTS 当作人工核验的声调数据。

### 4.3 跨页面划词

新增共用 `lookup_panel.js`，接入精听原文、真题学习/解析页、词汇语法例句。桌面选择文本后出现查询动作，移动端支持长按和明确按钮；浮层支持键盘、关闭与焦点返回。

收藏保存 `courseId/sentenceId` 或 `examId/questionId`、原句、选区和所选义项。同一词条可关联多个来源，新增来源不重复创建同一方向的复习卡。真题计时考试中沿用考试模式限制，查询不作为作答阶段的辅助入口。

## 5. 学习与复习方案

### 5.1 详情页的教学内容

| 词汇详情 | 语法详情 |
|---|---|
| 表记、假名、词性、义项及对应读音 | 文型、常见变体、接续规则 |
| 中文学习释义；词典原始义项分开展示 | 中文含义、适用场景、语气与使用限制 |
| 带来源的例句与翻译、常见搭配 | 分接续类型的例句、翻译与要点标记 |
| 常见活用、自他动词等关系（有可靠数据时） | 易混语法的适用条件与对比例句 |
| 发音、读音显隐、收藏与个人笔记 | 例句朗读、说明显隐、收藏与个人笔记 |

缺失字段标记“待补充”，不要用空白面板或无依据的 AI 内容代替。个人记忆提示与来源讲解分开保存、分开展示。

### 5.2 学习计划与每日任务

新计划支持按内容包、单元、选中条目、收藏和等级建立。一个计划可以引用多个内容来源；词与语法可合并复习，也可单独选择。计划保存已选择的稳定条目集合；以后新增符合筛选的内容，由“自动纳入新内容”设置决定，不能因索引变动静默扩大计划。

设置包括：名称、每日新条目数、顺序、练习方向、复习工作量提示、学习时区，以及暂停/恢复。删除计划只删除计划关系；删除个人卡片是另一项操作。

**计数契约：**

- 界面同时显示条目数和卡片数，例如“今天新学 10 个词，预计 20 张卡”。
- 新计划默认以条目为新学额度，选择的模板按条目展开；默认词汇先识义，语法优先合格的填空卡。
- 已有计划保留 `dailyNew` 的卡片额度语义，标记 `quotaUnit=card`；新计划使用 `quotaUnit=entry`，不无提示改变已有每日任务量。
- 同一全局卡加入两个计划后，只调度一次；“全部计划”总数按全局卡 ID 去重。
- 到期内容优先，新内容其次；复习负担过高时允许暂停新学。分批显示不改变卡片的真实到期状态。
- 同一条目的识义、读音、填空等方向独立评估；答对一个方向不自动掌握其他方向。

学习日由计划时区计算，同一天的批次生成一次。增补“批次头记录”，即使当天额度为零或无新卡，也冻结当日结果；修改每日量默认下一学习日生效。来源包更新、排序变化和刷新页面不能重新随机投放。

### 5.3 学习会话

会话保存队列、当前卡、展示状态、作答、完成状态和待重练项。刷新、切页或关闭后能恢复；恢复后的学习卡若已显示答案，不能重新标记为“独立回忆”。

每张卡经历：`待学 → 作答/回忆 → 显示反馈 → 记录结果 → 完成或待重练`。浏览详情只记浏览，不更新 SRS；打开答案只记提示暴露，不记客观正确。

卡片可跳过、暂停、收藏、记笔记、打开来源。跳过进入未完成集合，不能直接累计学习完成数。界面清楚区分：没有任务、已完成、加载失败、离线缺少缓存和有冲突待处理。

### 5.4 SRS 与本轮重练

保留现有四档长期调度及 Python/JavaScript 共用向量。`srs_stage=3` 继续称“成熟”，主动暂停仍由 `review_suspended` 控制。

补上两层调度：

1. **长期复习**：根据首次有效回忆/作答更新下一次复习时间，保留实际发生时间与幂等回执。
2. **本轮重练**：again、错误、蒙对、使用提示的卡片加入重练队列；默认隔至少 3 道其他题后再次出现，队列过短时放在本轮末尾。离开页面后仍保留重练任务。

本轮看过答案后的重做只影响本轮巩固结果，不重复增加长期成功次数，也不能冲掉首次答错记录。未来如引入分钟级学习步长，需要另加调度版本和迁移；本次先不替换整套算法。

`again / hard / good / easy` 的预期间隔由实际调度函数计算显示，不在按钮中写死。自评模式保留四档选项；客观练习由服务端根据结果生成建议，规则见下一节。

## 6. 练习功能与判题规则

### 6.1 词汇题型

| 题型 | 用户动作与反馈 | 出题前提 |
|---|---|---|
| 看词识义 | 选择与上下文匹配的义项，反馈为什么其他选项不合适 | 明确目标义项，合格干扰项 |
| 看词写读音 | 输入假名，显示读音差异和来源 | 题目限定表记/义项，提供有效读音集合 |
| 看释义回忆词语 | 输入或口头回忆表记，再看答案 | 默认自评；自动判分需显式限定语境和允许答案集合 |
| 听音识词 / 听写 | 播放后选择词义或输入词语 | 可用音频或明确标识的日语 TTS；有唯一目标或允许答案集合 |
| 例句填词 | 输入缺失词，显示搭配与词形解释 | 经审核挖空、语境和允许活用形式 |
| 搭配辨析 | 选择适合上下文的搭配 | 审核过的正解与每个干扰项解析 |

听音输入须考虑同音词：纯音频且缺少上下文时，优先判读音；不能因用户写了另一个合理同音词而直接判错。

### 6.2 语法题型

| 题型 | 用户动作与反馈 | 出题前提 |
|---|---|---|
| 接续选择 / 接续填空 | 选择或输入正确连接形式，指出词类与变化 | 结构化接续和审核后的题面 |
| 例句挖空 | 补全文型，显示完整句子和使用条件 | 稳定 exampleId、挖空位置、明确答案 |
| 近义语法辨析 | 在相近文型中选择，逐项说明成立或不成立的原因 | 每个候选有引用和解析；关系表不能直接充当判题证据 |
| 句子排序 | 点击或拖动片段排序；支持键盘移动 | 完整可接受顺序集合；重复片段使用独立 ID |
| 语境选择 | 根据前后句选择文型 | 语境充分、正解可证明、干扰项经审核 |
| 造句 / 改写 | 输入句子，对照检查接续、语义、语气 | 自评与参考答案；可选辅助点评 |

不直接将所有教材例句机械挖空后当作唯一答案题。允许多个文型时，要么提供约束、补充允许答案，要么降级为开放练习。保留现有 `usage.choiceRefs/answerRef/rationales`，由统一题目适配器解析成可显示选项和判题数据，修复前后端字段不一致。

### 6.3 组题、作答和解析

用户选择类型、等级/未分级、内容包/单元/收藏/错题、题型、数量（默认 10 题）和顺序，可进入即时反馈模式或整组提交模式。

- 按条目和能力方向平衡抽题，避免一组反复测试同一条例句；固定会话随机种子，刷新不换题。
- 只从具备该题型资格的题目组题；题量不足则明确显示可用数量并缩小集合，不用重复题补足。
- 选择题和填空在提交前允许修改；提交后记录原答案、规范化答案、首次结果、是否看提示、是否蒙答和有效用时。
- 解析包含正确答案、用户答案、依据、干扰项原因、来源、相关条目，以及加入复习/笔记的动作。
- 支持反馈“答案可能有误”；争议题进入待核对清单，该题后续记录可标为作废并重算统计，不能删除历史来掩盖错误。

### 6.4 判题与进度口径

| 场景 | 判定与调度 |
|---|---|
| 选择题 | 比较稳定 choiceId；选项洗牌不改变答案 |
| 读音输入 | 使用题型专用标准化：Unicode、首尾空白、允许的平片假名变体；浊音、促音、长音不能随意忽略 |
| 表记 / 文型输入 | 与当前题明确允许的答案集合比较；是否接受汉字/假名、标点和空格由题型规则决定 |
| 多空填空 | 各空单独反馈，所有必要空正确才算整题正确；保留部分正确信息 |
| 句子排序 | 比较 token ID 序列与有效顺序集合，不按拼接字符串猜测 |
| 开放造句 / 模糊产出 | 标记 `self_assessed`，不进入客观正确率；辅助模型的评价单独显示，不能伪装成确定正误 |
| 独立答对 | 默认建议 good；用户可自评困难，easy 只保留在明确自评流程 |
| 答错 / 跳过 / 提示后答对 / 蒙对 | 分开记录；答错和不可靠回忆进入重练，不能算独立掌握；跳过不推进长期成功次数 |

客观结果由服务端根据冻结题目和用户答案计算，客户端不直接提交“我答对了”作为依据。提供提示或显示答案后，该次答对归入辅助完成；自由练习与自评复习分别统计。

SRS 更新范围限定为对应的能力卡。词汇识义、读音、听辨以及语法接续/使用不能相互替代；新能力卡采用新增模板枚举，已有四种枚举和 ID 保持有效。无对应卡时，在用户已选择“练习结果加入复习”的会话里幂等创建，结果页显示新增数量。

### 6.5 错题与学习报告

记录“首次错误、提示后正确、蒙对、开放自评”四类结果，按词汇/语法、读音/意义/接续/辨析/排序筛选。可重做本轮错题、同知识点的新题或到期薄弱项；重做必须是新的作答记录。

报告分开显示条目覆盖数、完成卡片数、首次客观正确率、辅助完成率、重练结果、用时和下次复习量。没有客观作答时显示“暂无数据”，不能显示 0% 正确率。成熟数量是 SRS 状态指标，不作为考试掌握率。

## 7. 技术与数据设计

### 7.1 模块划分

```text
原生 JS 工作区与共用查询浮层
    ↓ 同源 API
Lexicon 查询 / 详情 API ── 内容索引 + 词典 SQLite + pack.json
Lexicon 学习 / 练习 API ── LearningStore + 新增会话/作答表
    ↓
learning.sqlite3：个人条目、卡片、计划、事件、笔记、错题
    ↕ 幂等同步
IndexedDB：卡片副本、练习会话、个人条目副本
localStorage：现有小型 outbox、墓碑、偏好
Service Worker：页面资源、经校验的内容包缓存
```

继续使用标准库服务，不为这次改动引入前端框架、Redis 或独立数据库服务。查词索引和练习引擎拆到独立模块，避免继续把全部逻辑追加到 `local_backend.py` 和 `lexicon.js`。

参考已有 `exam_engine.py` 的会话、答案版本和提交行为；词汇练习自行定义表和路由，不复用真题专有的卷面、分区、计时及考试提交状态。

### 7.2 身份与存储契约

保留 `lex:<packId>#<entryId>` 和 `(source_ref, prompt_type, variant_key)` 卡片键；同一来源内容的普通订正不改变身份。

词典新增可扩展引用格式，例如 `dict:jmdict#<entryId>:<senseKey>`。义项键由导入注册表维护，不能直接使用会因新版本插入而变化的数组下标；更新时明确匹配、拆分、合并和 retired，无法确定的关联保留旧快照并标记待处理。个人自建词条使用 `user:<uuid>`，不强制伪造教材来源。

| 数据表 / 结构（拟定） | 用途与约束 |
|---|---|
| 现有 `vocab` | 继续保存每个方向的 SRS 状态和来源快照；新增调度版本/能力标记时兼容旧行 |
| 新增 `lex_user_entries` | 按 sourceRef 保存个人收藏、笔记、标签、显示覆盖字段；没有复习卡也能收藏；原生个人词条正文放在这里 |
| 新增 `lex_entry_sources` | 一个条目的多个课程、句子、题目和收藏上下文；去重保留来源 |
| 扩展 `lex_decks` / `lex_deck_cards` | 配置学习范围、quotaUnit、模板、暂停状态；保留已有主键；新增来源和 retired 处理 |
| 新增 `lex_daily_batch_runs` | `(deckId, localDay)` 唯一；记录额度、配置版本和生成时间，允许空批次；原 `lex_daily_batches` 保存项目 |
| 新增 `lex_sessions` | 学习/练习模式、固定种子、题目/卡片顺序、内容与算法版本、状态、当前索引、恢复信息 |
| 新增 `lex_session_items` | 稳定题目 ID、题面与答案快照、选项顺序、能力卡引用、题型；受会话管理 |
| 新增 `lex_attempts` | 追加式作答事件：原答案、结果、提示/蒙答、时间、版本、operationId；不覆盖首次作答 |
| 新增 `lex_review_events` | SRS 变更前后状态及来源 attemptId，保留学习事件；`vocab_review_receipts` 继续承担旧接口幂等 |
| 新增 `lex_mistakes` | 可由作答事件重建的错题状态；支持待重练、巩固中、已解决和争议作废 |
| 内容扩展 | `fieldSources`、`qualityStatus`、`capabilities`、`exerciseTemplates`；题目含 acceptedAnswers、rationales、reviewStatus、revision |

收藏与个人笔记属于条目，SRS 属于能力卡，错题属于作答事件。三者分别保存，防止为收藏创建所有方向的卡片，或为每张卡重复存一份个人笔记。

内容包结构升级使用新 schemaVersion，提供 v1 读取适配和迁移命令；新增字段不改变原 entryId。版本升级后未认识新字段的旧客户端应提示升级，不能静默错判。

### 7.3 新增 / 扩展接口

以下是拟定接口，实施时统一加入现有令牌、Host、Origin 和请求体限制。现有 `/api/vocab*`、`/api/decks*` 和只读内容接口保留兼容。

| 方法与路径 | 行为 |
|---|---|
| `GET /api/lexicon/search` | 扩展 q、scope、kind、level、pack、unit、field、cursor、limit；返回命中原因、分页和词典可用状态 |
| `GET /api/dictionary/status` | 本地词典是否存在、版本、索引能力、更新状态 |
| `GET /api/dictionary/entries/<key>` | 词目、义项、读音约束及来源 |
| `GET /api/lexicon/entries/<slug>/<id>` | 扩展关联、可用题型和条目质量；修复质量限制绕过 |
| `PUT /api/lexicon/user-entries/<key>` | 幂等收藏、个人词条和笔记；来源与个人字段分离 |
| `POST /api/decks` / `PATCH /api/decks/<id>` | 扩展多来源、条目范围、模板、额度单位和暂停设置 |
| `POST /api/decks/<id>/serve` | 保留当日投放记录，同时明确哪些是尚未完成项目；页面不再把完整批次当作到期队列 |
| `GET /api/lexicon/today` | 到期卡、待学新卡、可恢复会话及统计；全部计划按卡 ID 去重 |
| `POST /api/lexicon/sessions` | 建立学习/练习会话，冻结内容版本和题目顺序 |
| `GET /api/lexicon/sessions/<id>` | 返回可恢复状态；在线未作答题不下发评分答案 |
| `POST /api/lexicon/sessions/<id>/answers` | 接受 itemId、answer、answerVersion、提示/蒙答状态、elapsedMs 和 operationId；服务端判题 |
| `POST /api/lexicon/sessions/<id>/submit` | 幂等完成会话并生成报告；重复交卷不重复推进 SRS |
| `GET /api/lexicon/sessions/<id>/report` | 作答、解析、统计、来源及重练入口 |
| `GET /api/lexicon/mistakes` / `GET /api/lexicon/stats` | 按类型/能力/时间聚合，供工作区和个人中心使用 |
| `POST /api/lexicon/sync` | 离线会话与作答小批量同步；按操作返回 applied / duplicate / conflict / rejected |

客户端 UI 对 400/404 等不可重试错误保留本地作答并显示原因；401/403 先重新获取会话，失败则等待重连；409 进入显式冲突处理；网络失败与可重试服务错误才自动排队。请求上限和版本校验服务端统一执行。

答题、错题派生、SRS 更新和幂等回执应在同一事务中提交；若为整组提交模式，则答题保存草稿，交卷时统一判分，不能半组已计分、半组未计分。

### 7.4 老数据迁移与内容修订

1. 用 SQLite backup API 生成一致性备份，增加 schema version 和迁移记录；在独立连接中检查迁移后数据完整性。
2. 原词条 ID、SRS 时间、复习次数、计划关系全部保留；新增表空表起步，不默认重置任何卡。
3. 把来源讲解放入来源快照，把用户可编辑字段迁入 `lex_user_entries`；历史上已被覆盖的笔记无法从当前行可靠恢复，只能在存在旧备份时对照恢复，不能承诺自动找回。
4. 旧 `vocab.note/tags/meaning` 中来源值与个人值无法完全区分时保留原值作为 legacy 个人副本，迁移报告标出待核对项，不根据猜测删除。
5. 内容修订只更新来源字段；旧练习保留开始时的内容/答案快照。新增条目进入未来批次；重排不影响身份；删除条目停止新投放并标记 retired，旧卡允许按已保存快照继续复习。
6. retired 之外的实质内容错误单独标记，不因保留快照而继续作为合格自动判分题；用户可查看旧记录与订正说明。
7. 卡片删除同步产生墓碑；计划对该卡保存排除意图，防止下一次同步自动重建。删除计划保留卡片和历史，两种语义分别测试。
8. 浏览器迁移成功并校验后才清理旧键；容量不足、事务中断、版本冲突时保留旧数据与可重试入口。

服务端新功能通过开关分阶段启用。回滚优先关闭新入口；如必须恢复数据库，保留升级后的完整文件及待同步操作，不覆盖升级后产生的学习记录。

## 8. 内容建设与出题质量

### 8.1 现有 N2 语法包修复

从现有 `pages/`、教材来源及已抽取例句建立缺项清单，按稳定 entryId 修订，重新 assemble 和 audit。不能为了消除警告统一填入占位释义。

每条进入正式学习的语法至少具备：中文释义、结构化接续、使用场景/限制、1 条完整例句及中文翻译、来源；每个进入自动判分的题目至少具备：可解释的题面、明确答案、解析和审核状态。多分支接续需要相应例句，不能只用一条例句证明所有分支。

对 191 条逐项完成补全或明确标记待核对；一期核心交付优先形成可用批次，最终内容验收要求现有 191 条全部有明确处理结果，未完成补全的条目不得计入“已完成学习内容”。当前 172 条释义缺失和 16 条例句缺失必须逐条销项，报告显示补全数、仍缺失数和原因。

### 8.2 首个单词内容包

建议首个可用交付包包含 **至少 300 个经核对的词条**，这是拟定验收规模，不是当前已有数量或 N2 全量词表。优先从现有 N2 精听课程和已安装学习内容提取候选，按实际语境连接词典义项；同形异义、不同读音保留区别。来源不能证明 JLPT 等级时标记未分级，不把“出现在 N2 课程里”等同于正式等级归属。

每条具备表记、有效读音、词性、中文学习释义、至少一条例句及翻译、字段来源。遇到无法确认的词典匹配时保留 ambiguous/unmatched 状态，待解决后才能进入正式学习。

词典全量查询和教材词汇包是两项交付：安装词典后可查询其中词目；中文释义与分级学习内容只覆盖已制作、已核验条目。界面分别展示词典版本和学习内容覆盖数量。

### 8.3 内容状态与功能资格

| 状态 / 条件 | 允许的功能 |
|---|---|
| 结构损坏、引用错误或审计 error | 列表显示问题摘要；不通过正式详情/发卡/出题接口提供学习正文 |
| 结构有效但内容缺项 | 允许浏览有效内容并提示具体缺项；按字段决定哪些学习方向可用 |
| 释义与读音等基础内容完整 | 开放对应识义、读音和自评学习卡 |
| 例句、答案、解析均合格且已审核 | 开放对应自动判分练习 |
| 近义关系存在但干扰项解析缺失 | 允许关系浏览；不开放辨析选择题 |
| 生成草稿或争议题 | 保留编辑/审核入口，排除正式自动组题 |

`capabilities` 从实际字段和审核证据计算，不能由单个 `reviewed=true` 无条件解锁。审核记录保存审核人/方式、时间、所依据来源和内容版本；正文修订后重新评估受影响题型。

### 8.4 生成与审核流水线

```text
来源提取 → 稳定条目匹配 → 字段补全草稿 → 词典读音/义项校验
        → 例句与解析核对 → 题型资格审计 → 题目预览与试答
        → 内容修订报告 → 原子安装 → 索引更新与卡片快照刷新
```

可复用现有 provider 配置生成中文解释、例句或干扰项草稿；模型输出必须保留生成来源和待核对状态。网络模型不可用时不影响已有查询、学习和判题，也不自动把本地教材发送到外部。正式练习使用已保存题目，不在每次答题时即时调用模型猜测正解。

对导入的内容包和个人 CSV/JSON 提供预览、字段映射、重复处理及错误报告。内容安装走临时目录校验后替换，不直接覆盖当前可用包；个人数据导入保留稳定 ID 或生成个人 UUID，不以词面简单去重掉不同义项。

## 9. 离线、可靠性与界面质量

### 9.1 明确三种运行状态

“断网”要区分互联网不可用与本地 Python 服务不可用；不能单用 `navigator.onLine` 判断 `127.0.0.1` 服务是否可用。

| 功能 | 本地服务运行、无互联网 | 本地服务关闭、浏览器有缓存 |
|---|---|---|
| 已安装词典查询 | 正常 | 不承诺全量词典；可查缓存内容与个人条目 |
| 内容浏览 | 正常 | 只浏览已完整缓存包 |
| 今日复习 | 正常 | 使用已缓存卡与会话；记录待同步事件 |
| 新卡投放 | 正常 | 只消费预先同步的批次，不自行增加服务端额度 |
| 客观练习 | 正常 | 使用提前准备的离线题目包，给出本地暂定结果，重连后核验 |
| 音频 | 已有本地音频可用 | 依赖已缓存音频；TTS 是否可用按浏览器实际能力判断 |
| 跨模式查询 | 正常 | 限缓存来源；缺失内容显示范围说明 |
| 模型辅助与词典更新 | 依赖具体本地/网络配置 | 不阻塞其他功能，待恢复再执行 |

浏览器离线练习需要携带判题数据，因此它定位于个人自学，不承诺防作弊考试。在线未作答接口不返回答案，离线预备包则明确携带版本化答案；两类入口不复用真题计时考试提交逻辑。

### 9.2 同步与失败恢复

- 所有评分/作答有稳定 operationId；同一请求重复重放只生效一次。按钮禁用防连点，数据库约束防重复。
- 新卡、作答事件与快照更新按依赖顺序同步；小型 outbox 保留引用与操作元信息，大题面/答案历史存 IndexedDB，避免将整份题包写入 localStorage。
- 跨 localStorage 与 IndexedDB 没有单事务，采用持久事件记录后再标记待同步、启动时扫描补偿的顺序。断电发生在任一步，都能恢复未发送事件。
- 只有网络错误可以显示“已离线保存”；业务拒绝显示“待处理”，不伪装成功。失败卡保留在会话，用户可重试或查看冲突。
- 使用卡片版本和答案版本检测多标签页并发，接受后广播/刷新状态；旧版本作答保留为冲突记录，不静默覆盖较新调度。
- 对晚到的离线评分沿用现有时间冲突保护；提供“保留练习记录、不覆盖较新 SRS”的解决方式。浏览器预测状态在获得服务端回执后校正。
- 统一个人中心和词汇页的删除、暂停、笔记更新事件；所有读取合并都应用墓碑。IndexedDB 故障时保留操作并显示恢复入口。
- 内容包缓存沿用版本写完再切换指针的思路，补齐清理旧版本、配额不足、失败回退及用户管理缓存的功能。

### 9.3 页面可用性与性能目标

词汇和语法页面适配桌面、平板和手机。选择题支持数字键，翻卡支持空格，提交支持 Enter；输入法组合阶段不提交，正在输入笔记时不触发全局快捷键。排序题除了拖动，还提供点击移动与键盘操作。

控件有可访问名称，解析变化可被读屏感知，对错用文字和图形共同表达。加载、空白、失败、无词典、无音源和无合格练习题都有独立状态。开发路径与原始错误信息放在诊断详情中，主界面使用学习者能理解的语言。

拟定性能验收目标，实施时记录机器、浏览器、索引大小、冷/热启动和数据版本后实测，不把目标写成当前性能：

| 项目 | 目标 |
|---|---|
| 已建索引的常用查询 | 预热后 API p95 ≤ 300 ms；统计不少于 200 条混合查询 |
| 查询输入体验 | 约 250 ms 防抖；旧请求不覆盖新结果；日文组合输入无误触发 |
| 日常 20 题组卷 | 已加载索引时 API p95 ≤ 1 s；不足题量明确返回 |
| 词典初始化 / 大包导入 | 有进度，可取消/恢复；完整文件验证后启用新版本 |
| 大列表 | 分页/按单元加载，不一次渲染全部词典 |
| 学习数据容量 | 1k/5k/10k 卡片下测导入、检索、升级和配额失败恢复 |

## 10. 实施阶段与交付顺序

优先形成可用的最小完整流程，再扩展题型和内容；阶段间沿用同一身份与事件模型。下面的工期是正常开发、评审、测试下的**工程人日估算**，用于比较规模，不是承诺完成日期；语言内容审核和来源整理单独计算。

| 阶段 | 任务与交付物 | 通过条件 | 估算 |
|---|---|---|---:|
| S0 现有缺陷与基线 | 修复 F01–F05；补来源字段保护、评分锁、质量策略、回归用例；同步现状文档 | 重载不重复完成卡，个人笔记不丢，错误不显示成功；既有学习历史兼容 | 3–4 人日 |
| S1 查询与详情 | 内容索引、假名/多字段查询、筛选路由、词汇/语法详情、收藏笔记、JMdict 构建和去活用 | 两类条目均可查询→详情→收藏；无词典降级明确；来源可追溯 | 5–8 人日 |
| S2 学习流程 | 新计划设置、每日批次、学习会话、恢复、卡片方向、短期重练、统计去重 | 可连续完成并恢复每日学习；完成/跳过/提示状态正确 | 4–6 人日 |
| S3 核心客观练习 | 词汇识义/读音、语法接续/填空、判分事件、解析、错题复练与报告 | 两类内容均走通选择范围→作答→判题→错题→复习 | 5–7 人日 |

| S5 离线、迁移与整体验收 | 离线题包、同步冲突、备份恢复、跨页一致性、移动端与全量回归、文档 | 验收矩阵通过，待审核内容与已实现功能分别报告 | 4–6 人日 |

合计约 **25–37 工程人日**。S0 完成后即可改善当前体验；S3 完成后具备查询、学习、核心练习的完整流程；S4–S5 完成且内容验收通过后，才称本次功能完善完成。

Python 与浏览器判题使用相同固定测试数据，覆盖正确/错误/多解/提示/蒙答、日文标准化、选项洗牌、多空和排序；SRS 延续原共享向量。高风险数据迁移、幂等和离线恢复必须有失败路径测试，简单展示文案不单独写镜像实现的测试。

## 12. 默认决策与实施边界

- **技术路线**：增量改造现有栈；一份个人学习数据库；一套卡片身份和长期调度。
- **学习组织**：统一工作区、统一今日队列，词汇与语法分别展示教学内容与练习。
- **交付顺序**：先修数据和队列缺陷，再查词/详情、学习、客观练习、扩展题型和完整离线验收。
- **内容优先级**：现有 N2 语法补全与首个可用词汇包；其他等级按内容来源逐步接入。
- **模型作用**：可辅助制作和开放题点评；核心查询、正式判题和复习在本地确定执行。
- **暂不纳入**：云账号/跨设备同步、社交排名、支付系统、整套 N1–N5 内容采购、汉字笔顺和专业语音评分。
- **完成定义**：功能、真实内容和回归验收分别列账，三者达到范围要求才标记完成；既有测试通过不能代替新增流程验收。

import json
import sys
from collections import Counter
from pathlib import Path
sys.path.insert(0, 'src')
from lexicon_store import LexiconStore

store = LexiconStore(Path('lexicon'))
for summary in store.list_packs():
    pack = store.get_pack(summary['slug'])
    templates = Counter(
        template.get('promptType')
        for entry in pack.get('entries', [])
        for template in entry.get('cardTemplates', [])
    )
    print(json.dumps({
        'slug': summary['slug'],
        'kind': summary.get('kind'),
        'entries': summary.get('entryCount'),
        'units': summary.get('unitCount'),
        'quality': summary.get('quality'),
        'templates': dict(templates),
    }, ensure_ascii=False))
print('dictionaryAssetsPresent:', Path('assets/dictionary').exists())
PY
