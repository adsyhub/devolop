# JLPT 题库

在原有听写播放器之外，本项目现在还带一个 JLPT 真题解题系统：导入一套真题后，可以
按所选范围逐题作答并在整组交卷后统一看解析，也可以进行计时练习，做错的题会自动进错题本并按间隔
重复安排复习。

- 页面：`http://127.0.0.1:4173/exam.html`（与听写播放器同一个服务、同一个端口）
- 入口：顶栏板块导航的「📝 JLPT 真题」，或启动时打印的第二行地址
- 数据：`exams/<名称>/exam.json`；作答记录写进听写用的同一个 SQLite 文件

已导入：`exams/2022-07-N1/` —— 2022 年 7 月 N1，105 题（68 道笔试 + 35 道听力 + 2 道例题），
共 176 分。

---

## 1. 三种练习方式

| 方式 | 行为 |
|---|---|
| **逐题练习** | 完成所选范围并交卷后统一判题，给出正确答案与正确排序，可写笔记、加标记 |
| **计时模考** | 作答时不显示对错，有倒计时和答题卡，交卷后一次性出报告 |
| **错题复习** | 只抽做错、蒙对、标记过或今天到期的题，完成整组后统一反馈 |

范围可以选全卷、某一部分、某一道大题（問題N），或错题 / 到期 / 已标记三种集合。
**练习范围决定计分范围**：只做問題1 且全对，历史记录里就是 6/6（100%），不是 6/176。

快捷键：`1`–`4` 选项，`←`/`→` 翻题，`M` 标记，`Enter` 下一题。

## 2. 蒙对不算会

作答时可以标注「有把握 / 不太确定 / 蒙的」。标为「蒙的」的题即使答对，连对次数也
不增加，仍然留在复习队列里——四选一蒙对的概率是 25%，把它当成「已掌握」推到几周
以后复习是自欺欺人。

复习间隔按连续「有把握且答对」的次数递增：1 → 3 → 7 → 16 → 35 天。

错题本区分四种结果，因为它们对应不同的补救动作：

| 结果 | 含义 |
|---|---|
| `correct` | 有把握且答对 |
| `guessed` | 蒙对 |
| `wrong` | 选错了——有一个错误理解需要纠正 |
| `skipped` | 没作答——通常是时间不够，不是不会 |

## 3. 听力题的限制

真题 PDF 里只有听力题的**选项**，题干和录音都没有。所以：

- 听力部分在题库首页和答题页都标注「需要音频」；
- 問題3、問題4、問題5 的 1 番在试卷上什么都不印（题干和选项都靠听），页面会明确
  说明「选项由录音朗读，试卷上未印出」，只能对照答案复习；
- 問題4 是**三选一**（`1から3の中から`），不是四选一，页面只显示 3 个选项。

如果以后拿到配套音频，可以按听写课程的方式挂进来；schema 里 `audioRequired` 已经
预留了这个位置。

## 4. 导入一套新真题
 
详细的完整执行指南、格式示例与 LLM 提示词见 [docs/JLPT_EXAM_PIPELINE.md](JLPT_EXAM_PIPELINE.md)。
 
分三步，只有中间一步需要人（或模型）读页面。

### 4.1 为什么不能直接抽文字

这类去水印的扫描件，内嵌字体子集没有可用的 `ToUnicode` 表。以 2022 年 7 月 N1 为例：

- `pdftotext` 抽 34 页只得到约 3000 个可读字符，日文全部丢失；
- PyMuPDF 能抽出字符，但每个字体的码位偏移量都不一样，抽出来是乱码。

所以没有可恢复的文字层，页面必须**看**。`exam_import.py` 负责它能负责的部分：渲染
图片、拼接跨页内容、套用答案、核对数量。

### 4.2 render —— PDF 转图片

```powershell
python src\exam_import.py render --pdf "dist\某某真题.pdf" --out .\exam-work\pages
```

每页输出四张图：

- `pNN.png` 整页（150 dpi）—— 只用来看版面结构，看哪个选项属于哪道题；
- `pNN_a.png` / `pNN_b.png` / `pNN_c.png` 三条重叠的横条（260 dpi 裁切后缩到 1500px）
  —— 用来逐字确认。

整页图不够看清假名：A4 在 150 dpi 下长边约 1750px，视觉模型还会再缩，`は/ば/ぱ`、
`つ/っ` 正是在这一步丢的。横条把同样的文字放大约三倍，且互相重叠，不会有内容卡在
接缝里。

需要 `pymupdf` 和 `pillow`，只有导入时才用得上：

```powershell
python -m pip install pymupdf pillow
```

### 4.3 转写 —— 每页一个 JSON

为每一页写一个 `pNN.json`：

```json
{
  "page": 12,
  "pageLabel": "第11页",
  "sectionHeader": null,
  "blocks": [ ... ],
  "issues": ["拿不准的地方都写在这里"]
}
```

`blocks` 的类型：

| kind | 用途 |
|---|---|
| `part-instruction` | 「問題N …一つ選びなさい。」开启一道大题，必须有 `partNumber` |
| `passage` | 阅读正文、A/B 两段、問題13 的方框案内；`label` 记印出来的 `(1)` `A` |
| `note` | `（注1）…` 注释，自动挂到它前面那段正文上 |
| `question` | 一道小题：`questionNumber`、`choices`，听力題另有 `label`（`1番`/`例`）和 `choiceCount` |
| `figure` | 无法用文字表达的插图，挂到它前面那道题或那段正文 |
| `section-header` | 「第三部分　聴解」，之后的 `partNumber` 按听力大题算 |

跨页的正文或选项，两半都写上 `continuesFromPreviousPage` / `continuesOnNextPage`，
`assemble` 会拼回去（正文按断在句中处理，中间不加分隔符）。

**文本标记**（`exam_schema.py` 是权威说明）：

| 写法 | 含义 |
|---|---|
| `<u>…</u>` | 试卷上画了下划线的部分 |
| `｜漢字《かんじ》` | 试卷上印出来的振假名。开头是**全角**竖线 U+FF5C |
| `【41】` | 正文里那个方框题号 |
| `★` | 排序题里带星的空格 |
| `\| a \| b \|` | 表格行；紧跟一行 `\| --- \| --- \|` 表示上一行是表头 |
| `> 文字` | 页面上画了框的提示段落 |

振假名用全角竖线不是随手选的：表格用半角 `|` 分隔单元格，用半角竖线做振假名标记会
让表格里的振假名没法解析（`tests/exam_markup.test.mjs` 里有这条回归）。

### 4.4 答案 —— 抄印在卷末的那张表

`answer-key.txt` 一行对应表里一格，方便逐行对着扫描件核对：

```text
note      此处给出的计分准则仅限参考…
written   1-6     1   133424        # 题号范围、分/题、每题一位数字
order     36      3241              # 排序题：四个片段的正确顺序
listening 1       1   321232        # 大题号、分/题、按顺序每题一位
```

听力答案按**位置**套用（第 k 道计分题拿第 k 位），因为听力题号每道大题重新从 1 开始，
而問題5 的一个「2番」会拆成分别计分的 質問1、質問2。

**答案存疑**。这些答案自称「非标准答案，仅供参考」，确实可能有错。发现某题答案可疑时，
用 `dispute` 行记下理由：

```text
dispute 58 卷末答案给的是 1，但原文「自分の偏狭な物の見方を問い直さなければならない」…
```

`dispute` **不会改动答案**——判分仍按印出来的答案走，只是在学习者看到判定结果的同时，
把这段争议一并显示出来（页面上是琥珀色的「答案存疑」条）。理由很简单：悄悄用编辑的
判断替换掉印刷答案，和答案本身抄错是同一类错误，而且更难被发现。把争议摆出来，让学习者
自己判断。

本卷已记录一处：**第 58 题**。

`order` 行会和答案互相校验：★ 永远是第三个空，所以 `order[3]` 必须等于该题答案。
2022 年 7 月这份卷子五道排序题全部对得上，这也反过来说明两行都抄对了。

### 4.5 assemble —— 生成 exam.json

```powershell
python src\exam_import.py assemble `
  --pages exams\2022-07-N1\pages `
  --key   exams\2022-07-N1\answer-key.txt `
  --meta  exams\2022-07-N1\exam-meta.json `
  --out   exams\2022-07-N1\exam.json
```

这一步会拼接跨页内容、把每道题挂到它该看的正文上、套答案，并且在数量对不上时**直接
报错停下**：

- 答案数量和页面上的题数不一致；
- 答案表里有页面上找不到的题号（多半是漏了一页没转写）；
- 页面上有题但答案表里没有；
- 生成结果没通过 `audit_exam`。

宁可报错也不能悄悄错位：答案一旦串位，学的就是错答案，而学习者没有任何办法发现。

`--allow-failed-audit` 只用于查看有问题的结果，不要用它发布。

### 4.6 核对

```powershell
python src\exam_import.py validate --exam exams\2022-07-N1\exam.json
python run_tests.py exam
```

`audit_exam` 有错误的卷子服务端**拒绝提供**（`GET /api/exams/<slug>` 返回 422），
题库首页也会把它标成停用，规则和课程的质量门一致。

## 5. 目录

```text
exams/
└─ 2022-07-N1/
   ├─ exam.json         播放器唯一需要的文件
   ├─ answer-key.txt    照抄卷末答案表，留着复核用
   ├─ exam-meta.json    标题、级别、来源 PDF 的哈希与版权说明
   └─ pages/pNN.json    逐页转写，内容的事实来源
```

`pages/` 保留在库里是有意的：`exam.json` 是生成物，改错字应该改 `pages/`
再重新 assemble，而不是手改生成物。题目 ID 由内容派生且稳定，改一道题的错字不会让
另外 104 道题的作答记录失效。

## 6. 接口

全部在 `/api/exams*`，和生词本走同一套授权（回环 Host 白名单 + 每次调用会话令牌 +
写操作校验 Origin 与 Fetch Metadata）。读接口也要令牌——作答记录是个人数据。

| 方法 | 路径 | 用途 |
|---|---|---|
| GET | `/api/exams` | 列出题库（不含题目正文） |
| GET | `/api/exams/<slug>` | 取整套卷子；未通过审计的返回 422 |
| POST | `/api/exams/<slug>/attempts` | 开始一次作答，带 `mode`、`scope`、`questionIds` |
| POST | `/api/exams/<slug>/answers` | 批量记录作答（≤500 条） |
| POST | `/api/exams/<slug>/finish` | 交卷，返回按范围计分的报告 |
| GET | `/api/exams/<slug>/attempts` | 历史记录 |
| POST | `/api/exam-attempts/<id>/abandon` | 放弃未完成作答（不计分） |
| GET | `/api/exams/<slug>/review` | 错题本与复习到期 |
| GET | `/api/exams/<slug>/stats` | 按大题的正确率、错题数、标记数 |
| POST | `/api/exams/<slug>/mark` | 标记 / 写笔记 |
| DELETE | `/api/exams/<slug>/progress` | 清空这套题的全部记录 |
| GET | `/api/exam-attempts/<id>` | 单次作答的逐题明细 |

`GET /api/exams` 的每套卷会带 `progress` 摘要，状态为 `not-started`、`in-progress`、
`completed` 或 `started`。未完成记录保留题目范围和逐题答案，页面可恢复到首道未答题；
离开答题页会保留进度，放弃只关闭本次记录、不触发交卷计分。逐题练习和错题复习依然必须
完成当前整组后统一交卷、统一判题。

专题训练的数量以来源真题整组计算。用户选择 3 套时，会纳入这 3 套真题在当前题型下的全部题目，
不会从某一套卷中只抽部分题；默认数量是当前题型的全部可用来源卷。

## 7. 两条边界

1. **答案随卷子一起发到浏览器。** 这是单机自学工具，进程是学习者自己的，听写播放器
   本来也把正确答案发给页面；藏起来只是做样子。真正要保证的是离线可用——Service
   Worker 缓存了卷子，一份判不了分的卷子不叫卷子。模考模式在**界面上**不显示答案，
   直到交卷为止，这才是有意义的那部分诚实。
2. **题目正文永远不经过 `innerHTML`。** 正文是模型读扫描件转写出来的数据，
   `exam_markup.js` 只用 `createElement` / `createTextNode` 构造节点，转写里出现
   `<script>` 就显示成那九个字符。`audit_exam` 另外会拦下不成对的 `<u>` 和任何其他
   标签，`tests/exam_markup.test.mjs` 对这两层都有回归。
