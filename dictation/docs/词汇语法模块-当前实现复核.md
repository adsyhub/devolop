## 一、已复现的功能缺陷

### 1. 在线刷新丢失练习输入（高优先级）

- 位置：`src/web/lexicon.js:779` 的 `loadSession()`。
- 复现：创建单词读音练习 → 输入答案 → 等待 700ms，确认 IndexedDB 已有 `drafts` → 刷新。
- 实测：本地保存了 `ここに保存した答え`，刷新后输入框为空，无 JavaScript 异常。
- 原因：没有待同步操作时，直接取服务端会话并覆盖缓存；只保留 `offlineQuestions`，没有合并 `drafts` 和 `pendingFeedback`。
- 影响：未提交答案、选择和排序草稿的刷新恢复不可靠；反馈阶段也存在同一路径的状态覆盖风险，后者本轮为代码检查结论。
- 对应：A10、R15。修复需按题目/轮次及会话版本合并客户端状态，并覆盖刷新及服务端已推进的边界。

### 2. “包含未审核题目”选项没有传给服务端（高优先级）

- 位置：`src/web/lexicon.js:767` 的 `createPractice()`。
- 复现：选 Everyday-words、看词识义、1 题，勾选“包含未审核题目”，点击开始。
- 实测：请求 JSON 没有 `includeDrafts`，返回 HTTP 400，仍提示勾选该选项。
- 原因：初次请求的 payload 没有读取复选框；仅在错误后的确认分支传 `includeDrafts:true`，而已勾选时又不会进入该分支。
- 影响：用户主动开启的待审题练习无法启动；后端支持不等于页面入口可用。
- 对应：A15、A20、R06。修复后还需检查题面、反馈和离线报告对待审题的明确标识及统计隔离。

### 3. 响应丢失时删除了待同步作答（高优先级）

- 位置：`src/web/lexicon.js:865–871` 的 `submitAnswer()` 异常处理。
- 复现：不预备离线题包 → 提交答案 → 测试代理先把请求实际发给服务端，收到 200 后丢弃响应。
- 实测：服务端 `cursor=1`，客户端 `cursor=0`，待同步操作数量为 0；页面提示本地服务不可用，保留原输入。
- 原因：没有 `full` 离线判题数据时，网络失败分支删除已经持久化的操作。网络失败并不能证明服务端未执行请求。
- 影响：失去使用同一个 operationId 获取回执的恢复路径，重试可能得到“已经提交”的冲突；不是服务端记录丢失，而是客户端无法正常确认成功。
- 对应：A04、A17、R16。应保留未知结果操作，重连后重放或查询原回执；“能否本地判题”和“是否保留待确认操作”必须分开。

### 4. 跳过后返回作答被 409 拒绝（高优先级）

- 位置：`src/web/lexicon.js:901` 的 `resumeSkipped()`；`src/lexicon_practice_store.py:393` 附近的轮次唯一性检查。
- 复现：1 题练习连续跳过三轮 → 点击“回到跳过的题” → 输入答案提交。
- 实测：HTTP 409，`这次作答已经提交，请载入最新状态。`
- 原因：前端只在本地队列追加 `round:0`，既未同步服务端队列，也复用了已经记录过的轮次。
- 影响：页面提供了继续作答入口，但该入口无法完成作答。
- 对应：A10、R15。需要服务端控制重新排队与有效轮次，并保留原跳过记录，不能只改客户端数组。

本轮使用 Chromium 实际执行输入刷新、待审题启动、响应丢失注入和跳过后重答；这四项均有复现证据。390px 初始浏览页未出现横向溢出，但不能据此宣布移动端、IME、无障碍及完整离线流程全部通过。
