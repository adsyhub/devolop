## 4. 统一计划卡与专项练习卡（LEX-01）

### 4.1 问题与目标

`_pack_card_map()` 按 `cardTemplates` 生成计划卡；`questions_for()` 自行生成默认题，`PracticeStore._apply_srs()` 又用题目 type/variant 直接生成 vocab ID。原本同一识义能力因此有两份 SRS。反过来，不同题型确实可能需要独立记忆状态，不能简单按 sourceRef 合并全部卡。

此外，专项创建的 reading、meaning、order 等卡保存 `cardPayload.exercise`，`renderStudy()` 只处理旧模板 cloze 和 production，其余显示词面并自评。到期的“读音输入题”会退化为普通翻卡，原有判题方向丢失。

### 4.2 目标契约

保留现有稳定 ID 算法，新增统一适配函数，例如 `resolve_review_card(pack, entry, question_or_template)`，计划发卡、专项首次答题和离线题包均调用它。

```json
{
  "reviewTarget": {
    "sourceRef": "lex:Some-pack#w_0123456789abcdef01234567",
    "promptType": "recall",
    "variantKey": "default"
  },
  "questionId": "q_opaque-id",
  "answerVersion": "sha256-of-scoring-content",
  "scoringVersion": 2,
  "presentationMode": "self"
}
```

- `reviewTarget` 决定长期卡身份；`questionId` 决定练习题身份；`answerVersion` 决定答案版本。三者分开。
- 沿用已存在的 recall/default；把自动构造的 recall 题映射到同一目标。
- 自动 production 采用固定默认目标；读音、义项选择等新增方向分别拥有明确目标，不强制合并。
- 同一例句同一空位沿用旧 cloze variant；新增例句生成新 variant，不能依据当前数组位置重新编号。
- 所有正式目标由服务端生成，客户端只提交目标引用与版本，不可自行指定任意 SRS 卡。

### 4.3 实现步骤

1. 在 `lexicon_exercise.py` 加入统一题目到卡片适配器；旧模板也转换为相同 QuestionSnapshot。
2. `LexiconLearning.pack()` 改为从适配器选方向，不仅过滤旧 `cardTemplates`。UI 能选的方向必须对应实际可生成目标。
3. `_apply_srs()` 使用 `reviewTarget`；将“首次有效作答更新 SRS”的事务逻辑提取为共用函数。日常复习与专项均复用该函数。
4. 日常复习遇到 exercise 快照时进入对应 choice/input/order/self 渲染与提交路径。旧纯手工卡继续翻卡自评。
5. 暴露合格题型与不可用原因，避免“具备 production 能力，但创建后空计划”。创建预览显示条目数、卡数与跳过原因。
6. 将详情/学习/专项代码逐步拆为 `lexicon_detail.js`、`lexicon_study.js`、`lexicon_practice.js` 等文件，并更新 HTML、SW 资源表。先完成契约测试，再逐块迁移。

### 4.4 旧重复卡处理

迁移必须先备份，再建立显式 `old_vocab_id → canonical_vocab_id` 映射：

- 只有一张有历史时保留其状态；两张都有历史时保留全部事件，默认选最近有效复习的状态作为初始规范状态，不把 repetitions 相加。
- 任一旧卡暂停时默认保留暂停，生成冲突报告；个人字段存在不同值时保留两份原值供恢复，不覆盖。
- 计划关系、批次引用、错题关联和历史事件关联指向规范卡；历史回执保留原响应，同时标明重定向。
- 不直接修改旧作答快照的题面和答案；新练习使用新映射，旧会话通过兼容适配解析。
- 浏览器同步收到 ID 映射后在事务内迁移快照、会话与待同步引用。无法确定的身份冲突保留待处理，不能猜测合并。

**验收**：同一词通过计划与专项各复习一次只存在一张指定方向卡；reading 到期仍要求输入读音；不同义项/不同例句方向不被误合并；内容修订后 SRS 历史保持。

## 5. 删除、并发、内容修订与迁移（LEX-02、03、13）

### 5.1 服务端持久删除意图

当前 `delete_vocab()` 物理删除行，专项 `_apply_srs()` 仅检查 `lex_user_entries.deleted`。在个人中心删除卡不等于删除收藏，因而后续练习可重新建卡。

新增或等价实现以下结构，名称为建议：

```sql
CREATE TABLE lex_card_tombstones (
  source_ref TEXT NOT NULL,
  prompt_type TEXT NOT NULL,
  variant_key TEXT NOT NULL,
  deleted_at TEXT NOT NULL,
  operation_id TEXT NOT NULL UNIQUE,
  version INTEGER NOT NULL,
  PRIMARY KEY (source_ref, prompt_type, variant_key)
);

CREATE TABLE lex_identity_aliases (
  old_vocab_id TEXT PRIMARY KEY,
  canonical_vocab_id TEXT NOT NULL,
  reason TEXT NOT NULL,
  migration_version INTEGER NOT NULL
);
```

实施要求：

1. 单删、批量删、导入覆盖、同步删都在同一事务中写墓碑、处理关系、删除活动卡。
2. `_materialize_source_card()`、`_apply_srs()`、计划同步和旧 outbox 重放均检查墓碑。学习记录可以接收，但返回 `srsApplied=false` 及明确原因。
3. “恢复卡片”必须是显式动作，带墓碑版本；收藏、普通编辑、内容升级不能顺带撤销删除。
4. 删除计划只删关系；删除收藏只删该收藏资产；删除复习卡只停止该方向的复习，保留历史。页面文案与接口使用同一语义。
5. 普通无来源卡按 vocab ID 建等价墓碑，不能让手工卡成为遗漏路径。

### 5.2 乐观并发和幂等

`expectedUpdatedAt` 当前未被服务端使用；而内容同步也会刷新 `updated_at`，因此直接把它变成卡片并发版本会产生无意义冲突。

建议增加 `review_version`，仅在调度/暂停/删除等影响复习的操作中变化。评分要求 `expectedReviewVersion`：

```json
{
  "vocabId": "v_opaque-id",
  "grade": "good",
  "reviewedAt": "2026-09-07T09:00:00+00:00",
  "expectedReviewVersion": 7
}
```

事务顺序：

1. 查 operationId 回执；同时验证资源、动作和规范化请求摘要。
2. 相同 ID、相同请求返回原回执；相同 ID、不同资源或内容返回 409。
3. 查墓碑、暂停状态、review_version 和事件时间；任一冲突都不推进 SRS。
4. 计算调度，写事件、卡片新状态、版本和回执，一次提交。
5. 网络断开后重复提交同一操作不会重复计数；相同旧版本但不同操作必须返回冲突。

专项 `answer()` 已有 session.version 与唯一约束，保留并补充请求摘要。`expose()`、会话创建和个人条目修改也要有相同的幂等约定。新增接口严格要求版本；旧客户端兼容模式明确记录来源并逐步退出，不能假装已经具备并发保护。

### 5.3 来源更新、退休与撤回

区分三种变化：

| 类型 | 新发卡 | 已有卡 | 已有作答 |
|---|---|---|---|
| 文字订正 / 单元重排 | 使用新快照 | 保留身份和 SRS，刷新来源字段 | 保留旧题版本 |
| 条目 retired / 来源移除 | 停止投放 | 保留快照并提示来源已移除 | 可查看原记录 |
| 答案有实质错误 / 题目撤回 | 停止正式出题 | 禁止继续按错误答案自动判分 | 标记受影响事件，按 §10 重算有效统计 |

包中的 alias 必须逐项解析并记录迁移；不按相同词面猜测。`source_revision` 从实际 entry 所属包取得，不能使用多包合成对象的首包 revision。个人覆盖字段保持，源解释放在 cardPayload 的来源部分。

### 5.4 数据库迁移执行规范

沿用 `lexicon_migrations.py`，将“只认 VERSION=1”改为有序迁移列表；每版单独记录成功状态。新增字段、回填、约束和报告按版本执行，失败不能留下“迁移完成”的标记。

- 备份须包含已有计划、练习和个人条目，不能继续仅按 vocab 是否非空决定备份。
- 先验证迁移可在副本重复执行；完成后检查外键、重复身份、事件数量、墓碑和待处理冲突。
- 旧版没有记录的操作历史无法凭空恢复。对无法判断的个人字段和重复卡生成报告，保留原始副本。
- 回滚优先关闭新入口；升级后产生的新记录保留为恢复数据，不能直接用旧备份覆盖它们。

**验收**：删除后新计划/专项/重放均不复活；重复和冲突请求区分；迁移失败可重跑；仅含 lex_sessions/lex_user_entries 的旧库也会备份；别名迁移保留历史。

## 6. 内容质量、出题资格与可复现制作（LEX-04、09、14）

### 6.1 分开生成、结构校验与内容审核

当前 `choice_spec()` 与补充生成器直接写 `reviewStatus=verified`；`questions_for()` 仅要求 evidence 非空。`notHumanReview=true` 本身不是内容一定错误的证明，但当前证据不足以证明多义词、干扰项、例句和语法语用已经核验。

实施为四态：`draft → machine_checked → reviewed → withdrawn`。结构审计通过只推进 machine_checked。reviewed 必须满足该题型具体审核要求；可以采用明确批准的审核流程，不能由生成函数自行授予。

建议记录：

```json
{
  "reviewStatus": "machine_checked",
  "review": {
    "method": "dictionary-match-and-structural-check",
    "reviewer": "",
    "reviewedAt": null,
    "contentHash": "hash-of-fields-being-reviewed",
    "checks": {
      "readingSenseCompatible": true,
      "exampleNaturalness": false,
      "answerCompleteness": false,
      "distractorRationales": false
    },
    "evidenceRefs": ["local-evidence-reference"]
  }
}
```

已有 verified 模板迁移为“审核待确认”，保留原标记和来源。当前 2,085 个显式模板需要逐项或按可核验批次给出审核结果。未经语义审核的生成内容可在草稿预览查看，但不计正式客观练习数量。

### 6.2 按题型决定资格

`capabilities()` 返回结构化结果，计划、详情、组题和题包导出统一读取：

```json
{
  "reading": {"available": true, "reasonCodes": []},
  "usage": {"available": false, "reasonCodes": ["review.required"]},
  "listening": {"available": false, "reasonCodes": ["audio.unavailable"]}
}
```

| 题型 | 最低要求 |
|---|---|
| recall / production 自评 | 含义与来源明确，缺项可显示，但不记客观正确 |
| reading | 所选表记、读音、义项兼容；答案集合有来源 |
| meaning | 目标义项明确；选项不能同义且同时正确；每个选项解析可解释 |
| cloze | 空位与原句对应，多空答案数量一致；语境能约束答案，合理多解在答案集合中 |
| connection | 指定语法与接续条件明确；不能只靠“未出现在列表”判定语言上一定错误 |
| usage / context / collocation | 场景足以区分；干扰项理由针对本题；无需推测其他词“绝对不能用” |
| order | 片段具备实际训练价值，全部合法顺序有依据；带标点的两段机械排序单独标为基础训练 |
| listening | 读音来源可靠，音源可用；语音不可用时不锁死整场会话 |
| writing | 自评模式或独立的建议反馈；开放表达不计客观正确率 |

`validate_spec()` 补题型/mode 组合、字段类型、答案长度、空数、重复选项文本、review 哈希和关联引用。正文/选项/答案改动使相应审核失效；更改无关 UI 元数据不必重审整包。

### 6.3 现有语法内容的剩余工作

1. 按 191 个稳定 entryId 导出审核清单，包括接续分支、中文说明、例句翻译、语境限制、近义关系和题型数量。
2. 逐条核对学习补充与来源；使用 `learning-supplement.json` 或独立补丁存审核修订，禁止手改最终 pack.json。
3. `confusables` 当前由编号分组生成；需要给关系添加类型、差异说明和至少一个有依据的比较场景。编号相邻不能等同于近义。
4. `usage` 当前通过中文释义选择文型，若没有近义对比依据，应改为“释义匹配”题型，避免用题型名称夸大训练内容。
5. 每条给出“审核通过/保留待审/撤回”结论。缺来源的补充不填写虚构 reviewer。

### 6.4 现有单词内容的剩余工作

1. 300 词的字段已齐全，重点是词典义项、搭配和模板例句自然度。当前 group 模板套用句子不等于逐词审核。
2. `senseIndexes=list(range(...))` 改为选定兼容义项；保存 writtenForm、reading、senseKeys 和词典版本。中文学习释义须映射到选中义项。
3. 对 25 个排除候选保留 `matched / ambiguous / unmatched / manually-resolved` 统计和持久裁决。每次构建说明候选总数、纳入数、排除数及理由。
4. 种子条目增加不可变 `seedKey`。当前按遍历次序生成 e0001…，在前面插入词会改变后续身份；改成注册表分配 key，新词追加，旧词移动不变 ID。
5. 保持当前 `ungraded`；没有级别依据不能因位于某课程中便改为 N2。

### 6.5 原子制作与安装

建议流水线：

```text
读取源页面/种子/裁决 → 装配基础条目 → 应用学习补充与审核记录
→ 固定身份检查 → 题型资格审计 → 计算最终 revision
→ 生成同 revision 的 match/quality/review 报告
→ 暂存目录完整校验 → 切换当前版本 → 刷新索引与卡片快照
```

- pack、注册表、报告必须作为同一发布单元；当前逐文件 `os.replace()` 只保证单文件原子性。
- 安装失败保留上一版本；临时产物可清理，当前版本不被半成品覆盖。
- 稳定注册表与审核补丁是源数据，生成物不能反过来作为唯一来源。
- 相同源、裁决、词典版本产生相同 revision；构建时间写报告元数据，不参与稳定正文哈希。
- 使用现有发布边界和来源策略；本次不改变教材包的分发规则。许可字段记录按已有政策校验，本文不重新认定外部许可条件。

**验收**：最终包与所有报告 revision 一致；变更一条答案使对应审核失效；移动种子顺序不改 ID；坏包无法替换当前包；正式可用数量与待审数量分别统计。

## 7. 学习计划、学习日与额度（LEX-06、07、13）

### 7.1 暂停的默认语义

`paused=true` 默认暂停该计划的新发卡及从该计划进入今日队列；不修改共享卡的全局 `review_suspended`。

“全部今日”按以下集合生成：

1. 活动计划所引用的到期卡集合。
2. 没有归属任何计划的个人到期卡。
3. 同一张卡同时属于活动计划与暂停计划时仍出现一次。
4. 只归属暂停计划的卡不被最后的全量 due 查询加回。
5. 全局暂停卡在所有来源均排除；会话恢复时也移除其待重练副本。

若产品希望暂停仅停止新学，应另设 `pauseNewOnly` 并改名展示，不能让单计划和全部计划对同一设置给出相反结果。

### 7.2 固定范围与方向

- 建立计划时保存选择结果的稳定 sourceRef 集合以及创建时 revisions。
- `autoInclude=false` 仅同步既有成员的内容修订；新匹配条目不自动纳入。
- `autoInclude=true` 才将新增成员加入未来批次，并在计划详情显示新增数量。
- 多包单元用 `(packId, unitId)`，不能只用 `u1`；当前裸 unitIds 会跨包误匹配同名单元。
- 方向由 §4 适配器展开；计划预览先计算资格，不允许以“创建成功、0 卡”替代无合格内容错误。
- 支持编辑名称、来源范围、方向、顺序、每日量和时区；现有页面主要只提供额度和暂停编辑，需补完整表单。
- 无内容包的个人条目/收藏计划使用统一 sourceRef 解析器；不要伪造教材包，也不要把“加入计划”悄悄变成一次练习。

### 7.3 批次与时间

保留 `lex_daily_batch_runs` 的空批次冻结能力，新增记录当日生效的 timezone、quotaUnit、dailyNew、配置版本和选择结果。

- 新计划按 entry 额度；旧计划继续 card 额度，不默默改变每日工作量。
- 同一条目展开多个方向时展示“条目数/卡片数”；汇总按全局卡 ID 去重。
- 全局已开始的卡加入另一个计划时只建立关系，不再次消耗“全局新学”额度；计划投放覆盖数可独立统计。
- 改额度、范围、方向、时区默认下一学习日生效；当前批次保持稳定。时区切换不能让同一日重新生成两批。
- `today()` 返回服务器计算的 `learningDay` 与每计划的批次键；浏览器不再使用自身 `toLocaleDateString()` 代替计划时区。
- 恢复本轮重练不应因浏览器跨零点而丢失；将“会话生命周期”与“每日投放归属”分开。
- 在一个数据库事务中完成计划 settings、主表和候选关系更新。当前 PATCH 先保存 settings，再修改 deck、同步来源，后续失败会留下部分修改。

**验收**：暂停集合规则完整；autoInclude=false 不扩容；跨包 u1 互不影响；选择 production 真正有卡；同日改量/改时区不重复投放；PATCH 失败不留下部分配置。

## 8. 离线、持久化与跨页面一致性（LEX-03、05、12、17）

### 8.1 所有提交先持久化

当前专项只有网络调用失败后才执行 `saveOperation()`。服务端写成功但响应丢失、本地在收到回执后崩溃，都可能导致下次请求重新生成 ID。

统一发送流程：

```text
输入/自评 → IndexedDB 原子写入 operation + 会话 pending 状态
→ 发送相同 operationId → 校验服务端回执
→ IndexedDB 原子应用回执 + 新会话/卡片状态 + 删除待发标记
→ 展示成功或下一题
```

- 网络异常、408、429 和可重试 5xx 保留 pending；遵守重试间隔。
- 400/404/409/422 记为 rejected/conflict，保留原答案并提供处理入口，不显示“已同步”。
- 鉴权过期重新 bootstrap 一次；仍失败时提示本地服务连接状态。
- 响应不可解析是协议错误，保留 pending 但不冒充已确定的离线成功。
- 提交锁是交互保护；最终正确性依赖稳定操作 ID、版本和数据库事务。
- 通用评分、暂停、删除和收藏也按此流程衔接。现有 localStorage outbox 可作为过渡入口，但同一操作只能有一个权威持久记录。

### 8.2 版本和提示事件

离线预备包除题目外需携带：sessionVersion、answerVersion、scoringVersion、已曝光状态和创建范围。当前只拷贝 `items`，在其他页面已更新会话时会得到不匹配的数据。

`reveal` 目前增加服务端版本，却没有作为离线重放操作记录：预备答案后在线看提示，再断网答题，必须能重建完全相同的版本序列。

- `answer / reveal / skip / submit` 使用同一会话单调 sequence，记录前驱 operationId。
- 依赖序列在 IndexedDB 事务内分配，不依赖 Date.now() 排序；多个标签页共享同一存储不能生成冲突序号。
- 同一会话冲突阻断其后继；不阻断无依赖的其他会话。
- 同步返回服务器完整规范状态；没有冲突的 pending 全部清除后再用服务端状态替换预测副本。
- 对已经保存的新复习，不用晚到事件倒退 SRS；旧答题可保留为历史，显式返回 `srsApplied=false`。
- 冲突归档需有可查看、导出和再次处理入口；目前“保留本地记录”虽写入 lex-meta，但页面没有完整归档访问路径。

### 8.3 离线功能范围

| 场景 | 目标行为 |
|---|---|
| 没有互联网，本地 Python 正常 | 本地词典、内容包、判题和复习正常 |
| Python 停止，已有完整包缓存 | 从该缓存解析列表、单元、条目详情；可按缓存字段查询 |
| Python 停止，已有日批次/卡片 | 消费已有任务并持久化事件；不自行增加新学额度 |
| Python 停止，已有离线题包 | 本地判题并显示暂定结果，恢复后核验 |
| 缺缓存/缺答案 | 明确说明缺什么，保留草稿；不显示“今天完成了” |

`openPack()` 已受 SW 包缓存支持；`detail()` 需新增从 READY 包按 entryId 查找的回退。搜索应构建缓存范围索引并返回 `availableSources`，不能继续只对个人对象 `JSON.stringify().includes()` 后宣称完整查询。

### 8.4 跨页面共享状态

1. 建立共用个人卡片仓库适配器，精听、个人中心、词汇页统一读写。
2. 每次变更写版本/墓碑后广播 `{entityType,id,version,operationId}`；每页建立长期 BroadcastChannel 接收端，避免每次发送都新建且不关闭。
3. storage/visibilitychange/页面恢复时执行补偿刷新；不支持 BroadcastChannel 的浏览器仍可工作。
4. 合并卡片和收藏均先应用 pending 与墓碑；不要把远程旧快照写回后复活本地删除。
5. 同一 sourceRef 的 `lex_user_entries.note` 与 `vocab.note` 明确归属：条目级个人笔记共享，方向专属记忆提示可保留在卡片。通过 adapter 展示，避免两边看似同一字段却互不更新。
6. 将旧 localStorage 卡片单事务迁入 IndexedDB；写入、数量和身份校验完成后才删除旧键。配额不足、被旧标签页阻塞、写到一半失败均保留旧副本。

### 8.5 缓存管理

保留 SW 当前“完整写入 revision 数据后切指针”的实现，补：缓存目录、占用估计、按包清除、旧 revision 回收、失败回退说明。清内容缓存与删学习记录是不同动作；有未同步事件时清理工具不得误删事件。

**验收**：预备→停止服务→答题/提示/跳过→刷新→恢复→重放，事件只生效一次；服务端已写但响应丢失可自动收敛；配额失败保留答案；个人中心删除后词汇页离线恢复不会复活。

## 9. 搜索、词典义项与安装更新（LEX-08、09、18）

### 9.1 修复真实分页

`_workspace_route()` 当前先取内容索引前 100 条，再混入最多 100 条词典结果，最后按 cursor 切片。总数和后续页面都只对截断候选有效，后置收藏过滤也会漏掉前 100 条以外的收藏。

目标 API 保留路径，升级查询语义：

```text
GET /api/lexicon/search
  ?q=...&scope=all|packs|dictionary|personal
  &kind=word|grammar&level=N1|N2|N3|N4|N5|ungraded
  &pack=...&unit=...&field=...&starred=0|1
  &limit=30&cursor=<opaque cursor>
```

返回 `results / nextCursor / hasMore / total / totalRelation / availableSources / indexRevision`。只有精确总数时用 `totalRelation=eq`；无法低成本精确统计则返回估计关系或不返回 total，禁止把截断数伪装成总数。

实现选择：优先在可重建的查询索引中统一存候选元数据；词典正文保留独立数据库。另一方案是多源分段游标合并，但每源必须继续读到足够结果，游标必须保存各源位置。

- 筛选在分页前执行；收藏从完整收藏引用集合反查，不对截断结果过滤。
- 排序冻结为 `(匹配等级, 常用标记, sourceRef)` 等稳定元组；跨页无重复无漏项。
- `scope`、field、unit/pack 组合严格验证；unit 必须限定到包，字典作用域不接受教材 unit。
- `scope=dictionary&kind=grammar` 返回空及原因，或明确 400，不能混入词汇。
- 索引 revision 改变后旧游标返回明确失效响应，前端从首屏刷新且保留查询条件。
- 不要仅依赖文件 mtime/size 判断所有语义变化；安装时传递内容 revision/索引代次并原子替换。

### 9.2 保留词典多义、多读音约束

构建器已保存 `readings[].restrictions`、noKanji 和 senses 的表记/读音限制。剩余工作是让消费者使用它们：

1. 搜索结果返回本次实际命中的表记和读音候选，不固定使用记录第一读音。
2. 详情提供兼容的表记→读音→义项选择，并显示义项注释。
3. 收藏保存所选组合、senseKeys、dictionaryVersion 和原始语境；同一 entSeq 不同义项不能互相覆盖。
4. 旧 `dict:jmdict#entSeq` 收藏迁移为“尚未选择义项”，保留旧显示快照；不要自动选第一义项作为已确认。
5. 为具体义项建立稳定的个人选择引用，保持词典词目引用与个人义项引用可互相跳转。旧卡 ID 通过显式映射迁移。
6. 字典更新导致当前基于内容哈希的 sense key 改变时，保留旧快照并生成重匹配候选，不静默替换释义。

### 9.3 去活用、罗马字与性能

当前规则已经支持多步候选和部分词性验证；应补测试和规则缺口，而非重写零散正则。

- 每步标明输入/输出词性限制、深度和代价；当前只保留最后规则 pos，应避免不兼容的连续变换产生假候选。
- 精确表记、精确读音、前缀和去活用结果保留命中链；同候选多链按最短有效链去重。
- 罗马字测试覆盖拨音、长音、促音、拗音、片假名外来语及常见输入别名；确实不支持的情况明确返回无结果，不做无依据自动更正。
- FTS5/trigram 缺失时保留精确/前缀，有界短词搜索；两字符英语释义等短查询要明确策略，当前小于 3 字符不走释义 FTS。
- 查询长度、候选量、页大小和超时均限流；SQL/FTS 特殊字符按字面处理。
- 在当前词典规模及 1k/5k/10k 内容卡规模测不少于 200 条混合查询，记录冷/热启动及 p95。建议热查询目标 ≤300ms，作为待验证目标。
- 前端增加约 250ms 防抖、组合输入保护、过期请求丢弃、命中高亮和列表返回位置；不把这些目标写成已实现。

### 9.4 词典更新闭环

保留现有临时构建、完整性检查和 `.previous` 备份，增加结构化作业：jobId、stage、bytes、entriesProcessed、startedAt、errorCode、cancelRequested。

- 在线安装接口支持查询进度、取消和失败重试；进程重启后能识别中断任务，不能只依赖内存 `self.job`。
- 默认重试从安全阶段重新开始；只有明确实现源校验和分段机制时才承诺断点续传。
- 词典库与 SOURCES 元数据采用版本目录/统一指针发布，避免库已替换而旁路来源文件未写成功。
- 前端不在轮询次数用尽但任务仍运行时提示“已更新”；显示仍处理中，可重新进入。
- API 安装入口只执行用户明确启动的下载，不在查词时自动联网。

**验收**：242 条匹配能够遍历完整；收藏过滤不漏；义项限制有效；词典缺失/损坏/更新失败可降级；新版本安装失败仍能用旧词典。

## 10. 作答流程、反馈、错题和统计（LEX-10、11、15）

### 10.1 隐藏答案与整组反馈

`public_question()` 已移除答案字段，但选项 ID 为 `answer`，仍透露正确选项。把公开选项 ID 改为与正误无关的 ID，在服务端快照保存映射；不能只调整展示顺序。

`feedback=end` 当前 answers 接口返回 saved，但 `_mistake()`、stats/mistakes 已在提交前更新，形成提前反馈旁路。修改为：

- 整组模式保存原始作答，未提交时公开历史只提供已保存答案/进度，不提供 correct、解析、错题或由本场结果推导的统计。
- 提交时统一生成反馈、错题和 SRS；或允许预计算但所有查询按会话反馈状态过滤，确保外部表现一致。
- 自评题在 end 模式无法先查看参考答案后评分，当前 UI 会撞上 reveal 冲突。默认创建时拒绝 self 题与 end 组合，提供改为即时反馈；若未来需要整组自评，另设计提交后自评阶段。
- 离线预备题包携带答案属于个人自学能力，应在 UI 明确说明；不把它当作严格考试保密接口。

### 10.2 会话状态与跳过

建议每个队列任务记录：`pending / answering / feedback / retry_pending / skipped_pending / completed`，以及 answerDraft、selectedOptionIds、orderedTokenIds、revealed、elapsedActiveMs。

- 输入、选项、排序与提示暴露写 IndexedDB；防抖保存，页面退出前补写。刷新不丢草稿、不重置已看答案状态。
- 反馈显示阶段持久化，恢复时先展示尚未阅读的反馈，不直接跳下一题。
- 跳过进入未完成集合，默认不计 answered；可以显式结束为 `completed_with_skips` 或 incomplete，并展示剩余任务。
- 当前 round<2 的上限防止无限循环可以保留，但到达上限后标记待后续巩固，不能声称全部掌握。
- 本轮重练不重复推进长期成功次数；第一次错误不可被本轮答对抹除。
- 同时区分自评前正常“揭示答案以核对”与提前提示；自评结果始终为 self_assessed，不算独立客观答对。
- 正在编辑笔记或使用输入法时不触发全局提交；组合输入事件单独记录，不能只检查 submit 事件上的 isComposing。

### 10.3 题目反馈、撤回与错题精度

`feedback()` 目前只插入 open 行。需要增加本地审核处理入口及以下状态：open、confirmed、rejected、resolved；保留处理人/方式、时间、修订引用和说明。

- 按 `(sourceRef, questionId或variant, answerVersion, exerciseType)` 保存可追溯问题；条目+题型汇总仅作为上层统计。
- 复练某一道错题应能选回原目标或同目标的新合格题；不能默认把该条目所有题型混入。
- 题目撤回后新会话排除；活动会话将相关题标为 unavailable 并允许跳过，不让用户被已撤回题阻塞。
- 历史作答保留，增加 validity/status 与撤回原因；统计只计算有效事件，并可以展示原始历史口径。
- 若错误答案已经影响 SRS，不直接回放并覆盖后续复习。先重算受影响链，生成修正建议；无后续事件时可按明确规则恢复，有后续事件时记录补偿事件和原因。

### 10.4 统计口径

统一 Python 与浏览器报告聚合：

- 条目数按 sourceRef 去重；当前离线报告按 itemId 去重，多个方向会高估条目数。
- 客观正确率只统计首次有效客观作答；提示/蒙答单列，开放题/自评/跳过分别列出。
- `answered`、`processed`、`skipped`、`remaining` 分开，不能把跳过当作答完。
- 错题汇总既保留首次错误次数，也保留后续独立复练成功；本轮重练不自动清除首次错题。
- 日历按已冻结的学习时区转换 reviewedAt；当前直接截 UTC 日期不足以表达学习日。
- 学习记录与 `/api/analytics` 对齐分类，避免个人中心只统计旧 vocab_review_receipts 而漏掉专项 lex_review_events。
- 数据量增长后按会话/时间分页，不能把 list_sessions 固定前 200 条当作完整历史。

**验收**：公开选项 ID 无答案语义；整组提交前所有公开入口不提前给反馈；刷新恢复草稿/反馈；跳过不会显示全部完成；作废题不污染当前准确率；线上线下报告口径相同。

## 11. 个人资产、导入导出和页面联动（LEX-12、16、19）

### 11.1 完整个人资料导出

目前页面导出 `state.users`，不含 contexts；后端 export 虽带 contexts，import 又只处理 items。因此现有导出再导入不能完整恢复收藏语境。

新增版本化个人学习备份契约，例如 schemaVersion=2：

- entries：稳定引用、义项选择、笔记、标签、收藏、删除版本。
- contexts：课程/句子或试卷/题目引用、原句、选区、来源 revision、保存时间。

- preview 显示新增、更新、冲突、重复、删除及不可恢复引用；明确按版本跳过旧数据还是人工处理。
- CSV 支持字段映射、字符编码说明和逐行错误；不强制把每次导入都当全新卡。

导出包含个人私有学习内容，只作为用户自己的备份；不改变现有内容包发布策略。

### 11.2 跨页查询和来源定位

2. 保存 courseId/sentenceId 或 examId/questionId、sourceRevision、选区起止、原句；旧 page/hash 作为兼容来源。
3. 浮层能显示候选活用链和义项选择，收藏不总是取词典首读音。

5. 真题计时模式禁用，学习/解析模式开放；通过宿主状态测试，不扩大到计时考试辅助。

### 11.3 路由、音源与无障碍

- 搜索筛选、分页、单元、条目、练习范围写入 URL 或有 ID 的持久配置。当前 planRefs/practiceRefs 只在内存，刷新会丢失定向范围。
