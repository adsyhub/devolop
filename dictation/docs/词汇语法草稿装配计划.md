## 2. 装配管线的五道闸门

每一道都是 fail-closed 的，**没有一道可以绕过**（`--allow-failed-audit` 只用于查看，不写包）。

| # | 闸门 | 命令 | 通过条件 | 实现 |
|---|---|---|---|---|
| 1 | extract | `lexicon_import.py extract --document … --out … --kind grammar\|word` | 写出 `pages/p*.json` | [lexicon_import.py:204](../src/lexicon_import.py#L204) |
| 2 | 人工 | 改 `pages/`、填 `units.txt`、填 `pack-meta.json` | 无 error 页；每行有整数计数 | [lexicon_import.py:686](../src/lexicon_import.py#L686) |
| 3 | assemble | `lexicon_import.py assemble --pack … [--accept-new-keys]` | ①`units.txt` 无 `?` ②逐单元对账相等 ③`audit_pack` 0 error | [lexicon_import.py:1153](../src/lexicon_import.py#L1153) |
| 4 | supplement | 放 `learning-supplement.json`，由 assemble 自动应用 | 补 `gloss.zh`、例句、`exerciseTemplates` | [lexicon_content.py:28](../src/lexicon_content.py#L28) |

### 2.1 第 3 道闸门的三种拒绝，逐条说明

**① `units.txt` 里的 `?`**：现在 6 份草稿**每一行都是 `?`**（36–51 行/本）。

```
第1週 1日目 アパートを探しています ?
第2週 2日目 仕事をしています$\ ?     ← 还带着 OCR 的 $\ 垃圾，标题要一起清
```

`parse_units_file` 会点名报错并拒绝继续。条目数**不能从 OCR 推**——那等于让检查项核对它自己。

**② 目次对账**：逐单元比对「units.txt 声明的条目数」与「pages/ 实际抽到的条目数」，
任一单元不等就拒绝写包。按 §1.4 的分布，六份现在全都会在这一步炸。

**③ `audit_pack` 的 error**：按 §1.3，词汇/汉字书会有 65–314 条 `entry.chinese_missing`。
语法书还会有 `grammar.connection_missing`。

## 4. 轨道 A：N3语法（最短路径，建议先做这一条）

N3语法与 N2语法版式完全相同：灰底标题条 + 浮动接続框（`> ` 引用行）+ 四语例句翻译。

再用台账去 OCR 文本里定位、绑定接続框和例句，**并顺手写出 `units.txt`**（计数来自台账，不是 OCR）。

N3语法的 OCR 里「今週の表現」出现 6 次（6 週），台账齐全，这条路线可以直接复刻。

### A5 编写学习补充（144 条中文概括）

语法书的中文必须自己写（书上只有例句译文，没有逐条释义）。格式照
`lexicon/N2-grammar-soumatome/learning-supplement.json`：

```json
{
  "schemaVersion": 1,
  "provenance": {"sourceType": "original-editorial", "author": "...",
                 "method": "结合条目接续、既有例句与日语释义编写中文学习概括；新增例句为原创。",
                 "createdAt": "2026-09-..."},

  "confusableDetails": {}

```

**两个坑**：

1. `meanings` 是**按位置**映射到 `e0001…` 的（[lexicon_content.py:33](../src/lexicon_content.py#L33)）。
   数组顺序必须与 entryKey 顺序严格一致，插一条会整体错位。写完先跑一遍对照抽查。
2. `supplement_pack` 里的近义词分组是**写死的 N2 条目号**

   直接拿来跑 N3 会生成一批**错误的近义词对照**。装配 N3 之前必须先把它改成从
   `learning-supplement.json` 的 `confusableGroups` 读取，默认空。**这是代码改动，不是内容工作。**

## 5. 轨道 B：两本词汇书（N3词汇 / N2词汇）

### B1 为什么现在抽不到

见出し語 的判定规则要求**该行后面跟一个空行**
（[lexicon_import.py:512](../src/lexicon_import.py#L512)，`_followed_by_blank`）。
这条规则是为语法书的标题条设计的，能防止「れい」列表被切成八条。

但词汇书是图解版式，每个词紧跟着译文行，中间没有空行：

```
エプロン
apron 围裙 에이프런
```

于是 `エプロン` 不被认成 headword，反而是排版里零星的独立日文行被抓进来——
这就是「中位长度 5 字、0 条有中文释义、8–19% 见出词是垃圾」的由来。
**这不是 OCR 质量问题，OCR 文本是好的；是抽取器版式不匹配。**

### B2 写图解词汇版式抽取器

新增 `--layout picture-vocab`（或独立的 `lexicon_import_words.py`），规则：

| 要素 | 识别依据 |
|---|---|
| 条目起始 | 一行日文 + 紧随的「英文 中文 韩文」三语行 |
| 三语行 | 用现成的 `script_of()`（[lexicon_import.py:152](../src/lexicon_import.py#L152)）判 latin / han / hangul 共存 |
| 条目读音 | 見出し語 下方单独的假名行。现在它只是被排除在 headword 候选之外（`_KANA_RESIDUE`，[lexicon_import.py:564](../src/lexicon_import.py#L564)），然后落进正文噪声。新抽取器要把它收进条目级 `snapshot.reading`——`reading_of()` 认这个字段（[lexicon_exercise.py:80](../src/lexicon_exercise.py#L80)），`listening` 题型也靠它 |
| 例句读音 | **不要写**。`READING_SOURCES` 只接受 `dictionary` / `manual`（[lexicon_schema.py:81](../src/lexicon_schema.py#L81)），给例句挂一个 OCR 来的读音会直接触发 `example.reading_unsourced` error |
| 搭配短语 | 「もっとおぼえましょう」之后同样的三语结构，作为同一日目的独立条目 |
| 截断 | `れんしゅう` / `練習` 之后全部是练习题，归题库，不进包 |
| 排除 | 页脚「17ページの答え：」、「きょうの一言」 |

中文直接取书上印的（`fieldSources = textbook-ocr`），**不要再走 §A5 那种编写路线**。

### B3 用索引当台账

书末 さくいん 每项是「词……页码」，而页码 → 週/日目 的映射从 `unitHeader` 已知。
因此可以机械生成 `units.txt` 的计数候选，**再由人对着书抽查若干单元确认**。

这里要守住一条线：索引是书自己印的独立台账，可以用；
从 OCR 抽出来的条目数**不可以**回填进 `units.txt`。

### B4 装配

同 A1（命名 `N3-words-soumatome` / `N2-words-soumatome`）、A4、A6、A7。

### B5 练习模板

词汇条目该有的题型是 `meaning` / `cloze` / `collocation` / `listening`，
现有生成器在 [lexicon_content.py](../src/lexicon_content.py) 的 `build_words()` 里，
但它是给 `assets/lexicon_seed/` 那套原创种子写的，绑着 JMdict 匹配与裁决文件。
教材词汇包要复用它，需要把「生成题型」和「种子来源」解耦——**建议 B 轨第一版先不生成练习模板**，
只出可浏览、可背诵（recall/production 由 `default_card_templates` 自动给）的包，
练习模板留到词典匹配（Phase B）接上之后再补。

## 6. 轨道 C：两本汉字书（N2汉字 / N3汉字）

版式又不一样，条目单位是**熟語行**：

```
営業 business 营业 영업
準急 じゅんきゅう a semi-express train 普通快车 준급행
```

- 与轨道 B 共用三语行识别，但**没有图解、没有例句**（`examples_missing` 135/148、51/103），
  条目主体就是「熟語 + 读音 + 三语释义」。
- 台账是「漢字・語彙リスト」（N2 p143+、N3 p111+），按画数排列并带页码，可当索引用；
  但 N2汉字 的列表页有一半被 OCR 成了 Markdown 表格（`| 両方 | 20 | 許可 | 108 |`），
  转写脚本要同时吃两种形态。
- 汉字包的 `kind` 仍是 `word`（schema 只有 word / grammar 两种），
  级别字段照填 N2 / N3，`headword` 取熟語，汉字本身进 `notes`。

工作量上 C 轨是 B 轨的延伸，建议**紧接 B 轨做**，不要并行——三语行解析器只写一次。

## 9. 风险与明确不做的事

**不做**：

- 不为了让 `assemble` 跑通而给 `units.txt` 填一个「看起来合理」的数字。那会把整条管线里
  唯一的独立校验变成 OCR 的复读机。
- 不手改 `pack.json`。`contentRevision` 对不上会被 `pack.revision_stale` 挡掉。
- 不在词汇/汉字包里冒充教材原文写中文；书上印了就抽，没印就留空并标 warning。
- 不把 `reviewStatus` 直接写成 `reviewed`。签字需要 reviewer + contentHash，见 §11 的存量问题。

**风险**：

| 风险 | 说明 | 对策 |
|---|---|---|
| 台账转写出错 | 144–864 条手工核对，是整条链上最容易出错的一环 | 双人交叉抽检；台账进版本库便于 diff |
| 索引页 OCR 不全 | N3词汇 p110/112、N2词汇 p147–149 的识别项数异常低 | 转写时对照原书补，不靠 OCR 计数 |
| 词汇包条目量大 | 单本 800+ 条，逐字抽检成本高 | 按「每日目至少一条」抽，覆盖每类抽取路径即可 |
| 重复 OCR | studio 已经把同一本书跑了两遍（N2语法、蓝宝书N2文法各两份） | 阶段 0 的 sha 查重 |
