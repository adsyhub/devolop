# 功能完善分析与产品实施清单

基线日期：2026-09-07。依据：当前 Web 页面、交互代码、API、评分和会话实现；评分反例做了独立函数验证，其余为源码流程核查，未执行浏览器端到端验收。本文补充 [项目复核与实施计划](PROJECT_REVIEW_2026-09-07.md)，侧重用户能完成什么操作、还缺什么体验。

## 1. 功能判断

当前已经能完成“选一套卷 → 作答 → 提交 → 查看对错与记录”，但还没有形成完整的“选合适的题 → 稳定作答 → 看懂错误 → 针对性重练 → 观察进步”学习流程。

功能完善分三类：

- **先修正已有行为**：正确率统计、记述判定、保存与交卷、按钮无效、完整卷/模考能力显示。
- **补齐学习流程**：续答、答案与解析、错题重练、收藏笔记、历史复盘。
- **扩展学习能力**：专项组题、知识点、复习安排、学习报告、日本语听力和记述评阅。

## 2. 优先修正的现有功能

| ID | 功能问题 | 当前表现与影响 | 应达到的行为 |
|---|---|---|---|
| U01 | 正确率统计 | 2道题只答对1道、另1道未作答，汇总返回1/1、100%；分科返回1/2 | 显示客观题总量、已答、未答、正确、错误；整卷正确率=正确数/客观题总数；如另给已答正确率，明确命名 |
| U02 | 记述和未答状态 | 记述后台为PENDING_REVIEW，但前端用correct真假判断，显示“回答错误”；仅错题筛选也会包含它 | 正确、错误、未作答、待评阅分别展示；记述不纳入客观正确率；待评阅单独筛选 |
| U03 | 保存与交卷 | 保存失败后交卷仍可能继续；不能确认最后一次输入已保存 | 明确显示未保存/保存中/已保存/失败；失败可重试；保存未确认禁止主动交卷 |
| U04 | 暂停和结束状态 | 暂停仅改变服务端状态和按钮，题目输入未禁用；交卷后仍可回工作区修改界面输入，但服务端拒绝 | 暂停先保存，再遮罩或禁用输入；结束后只读；保留明确继续/返回/新练习入口 |
| U05 | 模式与时长提示 | 页面始终提供模考，未依据卷可用模式限制；配置时长是固定80分钟文案；科目旁显示固定分值信息 | 只显示该卷可用模式；未开放说明原因；根据所选内容显示题量和时长，以实际规则配置为准；本练习结果保持原始统计口径 |
| U06 | 未接通的控件 | 打印/导出无事件；错题状态下拉未用于过滤；图片放大函数未在题图上绑定 | 每个可点击控件有完整行为、成功反馈与失败提示；尚未提供的功能明确隐藏或禁用 |

这些是修正已有功能，优先于新增学习模块。历史结果统计若需要纠正，应保留旧结果及评分规则版本，明确展示重新计算后的口径。

## 3. 学习功能逐项完善

### 3.1 试卷库与找题

现有：按回次、科目、完整度筛选试卷。

需要补充：

1. 试卷详情：实际题量、题型、语言、可练分区、预计时长、复核状态、缺少内容和最近练习记录。
2. “继续上次练习”入口，避免只能重新开始。
3. 语言、数学Course、知识点等筛选；题干关键词搜索。
4. 题目级检索，支持“未做过/做错过/已收藏”；跨卷搜索保留来源与版本。
5. 题库概览：可用多少卷、多少题，哪些仅可部分练习。缺音频等原因用易懂文字解释。

首版范围：先做详情、继续入口与语言/Course筛选；知识点检索依赖内容标注。

验收示例：用户能找出一套指定语言的数学C1卷，在开始前知道题量、允许的模式以及是否存在未复核内容。

### 3.2 按需练习与组题

现有：选择一套卷内的科目；前端只有PRACTICE/MOCK，没有真正的SECTION流程。

需要补充：

- 分区练习：只练读解、记述或一组材料题。
- 题量配置：例如一次10题；可选未做题、错题或收藏题。
- 知识点专项：例如力学、概率、阅读主旨等，由复核过的标签支持。
- 顺序/随机练习；共享材料题和依赖题作为一组抽取，保留内部顺序。
- 自由练习可设置“每题提交后查看答案”或“整组结束后查看”；模考结束后统一查看。

首版范围：错题/收藏集合练习和按分区练习。随机抽题不默认打乱答案选项，防止图形选项、数字格或关联题失去对应关系。

验收示例：用户选择“物理错题10题”，得到独立练习记录；材料题上下文完整，不能混入已停用或未复核题目。

### 3.3 答题工作区与续答

现有：全卷纵向显示、题号跳转、答题标记、延迟自动保存、暂停和倒计时。

需要补充：

- 刷新、关闭后重新打开、服务重启后的继续作答；恢复答案、当前题、选科、计时和笔记。
- 单题/整卷视图切换，上一题/下一题、仅看未答、只看存疑、完成进度。
- “本次存疑标记”与“长期收藏”分开，避免临时做题标记污染收藏夹。
- 数学数字格区分未填、部分填写、填写完成；展示缺少哪些格位。
- 移动端题号抽屉、图表放大、共享材料固定查看；字体大小和键盘操作。
- 交卷前显示未答数量与题号，允许返回补答。
- 网络故障时保留本地草稿、显示最后确认时间，恢复后重试。

验收示例：输入作文后刷新，文本和光标附近位置可恢复；最后几秒输入的处理规则明确；暂停时不能继续改答，提交后不能改动本次记录。

### 3.4 结果页：从“知道错了”到“知道为什么错”

现有：正确率、分科正确数、逐题对错和本次内存里的作答。未提供正确答案展示、完整选项/材料复盘及解析阅读流程。

需要补充：

1. 每题完整题面、材料和选项，与“我的答案/正确答案”并排展示。
2. 解题步骤、考查知识点、常见误区；没有解析时明确显示“暂无解析”。
3. 数学按格位标出正确、错误和漏填；整题结果与格位统计分开。
4. 正确、错误、未答、待评阅筛选；给出错题与未答题重练入口。
5. 记录时长与节奏；只有采集过可靠时间数据才显示逐题耗时。
6. 历史结果从数据库独立加载当时题卷和答案，不依赖当前正在做的卷。

答案和解析从已提交会话的复盘接口获取；自由练习的逐题查看需要独立授权状态，不能把正确答案提前下发到整卷学习接口。

解析先支持人工维护；中文翻译作为可展开的辅助内容，注明来源和复核状态，不覆盖日文原题。自动生成解析可作为后续制作助手，未经复核不作为已确认答案说明。

验收示例：关闭网页后重新打开某次历史记录，仍能看到当时题面、作答、正确答案和正确的状态；对内容修订有明确提示。

### 3.5 错题复习

现有：错题列表、做错次数和“标记为已掌握”。下拉筛选尚未接通，也没有直接作答流程。

需要补充：

- 科目/知识点/状态/时间筛选、批量选择、直接重练。
- 错因：知识点不熟、读题错误、计算错误、时间不足、猜答；支持自由备注。
- 最近几次重做记录、最近正确时间、再次做错后的状态回退。
- 复习日期与到期列表；先使用用户可调整的简单间隔，不必先做复杂推荐算法。
- 明确“未答题”是否进入待练清单，避免与“答错题”混为一类。
- 自动掌握规则如需启用，应允许用户理解和覆盖；不能只根据一次答对判断永久掌握。

验收示例：一题今天做错、重练正确、之后再次做错，系统能显示每次记录并重新进入待复习；知识点统计不把重复练习当作多道独立题。

### 3.6 收藏与笔记

现有：收藏/笔记后端接口；工作区可切换收藏，但新会话未加载已有收藏；没有完整收藏页和笔记编辑器。

需要补充：收藏列表、筛选、批量重练、笔记编辑与自动保存、按笔记搜索。首版允许一题一条可编辑笔记；个人错因、理解和解析内容分开。

验收示例：在题目上写一段笔记，刷新和下次练习仍可查看；收藏题可组成一组练习；取消本次存疑标记不删除长期收藏。

### 3.7 历史、学习报告与安排

现有：练习历史表，显示时间、科目、状态和成绩；尚无完整分析或学习计划。

先补：按时间/科目筛选、未完成会话继续或放弃、历史详情、真实练习时长、每次使用的卷版本。

再扩展：学习日历、每日目标、待复习数、周报、知识点掌握图、不同回次表现。报告至少区分首次作答与重做正确率、独立题数与作答次数、未答与答错。知识点“薄弱”结论要显示样本量，不以一两题下结论。

验收示例：用户能知道本周首次做了多少道题、复习了多少道旧题，以及明天有哪些待复习内容。

### 3.8 日本语听力与记述

现有：音频处理和Range支持的一部分底层函数；页面无完整听力播放器。记述有输入框和字数显示，提交后后台待评阅，前端状态展示存在U02问题。

听力需要：播放/暂停、练习模式重播和变速、按题定位、音频加载失败提示、听力原文按练习状态展开、分区顺序与进度恢复。严格模考按已核实的规则控制重播与跳转；没有音频时明确只开放可用分区。

记述需要：草稿恢复、字数统计口径、按题配置字数范围、全文复盘、自评/人工评阅入口、评价维度与修改记录。未提交和未评阅作文不应显示成客观题错误。

验收示例：合成日本语材料可走完听力和记述流程；作文提交后进入待评阅，人工评阅后能对照原稿与意见。真实卷另外要求音频、答案和内容复核到位。

## 4. 内容维护者功能

| 功能 | 现状 | 应补到什么程度 |
|---|---|---|
| 来源导入向导 | 主要依靠CLI和脚本 | 选择文件、回次/科目/语言、检测重复、显示缺少资料；导入后先进入待处理 |
| 制作任务中心 | 没有完整管理界面 | 页级进度、失败原因、重试、取消、查看产物；长任务不能阻塞学习 |
| 原卷复核 | “内容复核台”仅显示清单 | 原页与题文并排、图形框选、答案核对、修改差异、签署与撤回 |
| 题目编辑与分类 | 需要手工改JSON | 编辑材料/题干/选项/答案格、关联图片、标签、解析和翻译；预览与学生看到的内容一致 |
| 发布检查 | 有CLI发布和基础审计 | 列出未完成事项，明确COMPLETE/PARTIAL、开放模式、版本差异；发布后内容清单同步 |
| 学习中纠错 | 没有反馈入口 | 每题“报告问题”：类型、说明、引用版本；维护端能处理、复核并发布修订 |
| 数据管理 | 有备份/恢复命令 | 页面显示上次备份与验证结果，导入恢复到新目录后预览；学习报告可打印/导出 |

维护端最先做“原卷复核 + 问题处理 + 发布检查”。现有内容已发现来源不一致问题，继续增加题量前必须具备可重复的核对流程。

## 5. 实施优先级和交付批次

| 批次 | 优先级 | 交付功能 | 用户验收场景 |
|---|---|---|---|
| A：当前功能可信可用 | P0 | U01–U06、可靠保存、暂停/结束只读、内容状态和模式提示、最小复核 | 部分未答正确计分；作文不判错；保存失败不交卷；现有可见控件全部有用 |
| B：学习流程完整 | P1 | 刷新续答、历史独立回看、提交后正确答案、基础解析、错题重练、收藏笔记 | 一次练习中断后能继续，提交后能看懂错误并重新练习 |
| C：专项与全题型 | P1 | 分区练习、按条件组题、数学格位反馈、听力播放器与分区、记述评阅、制作任务管理 | 理科/数学/综合/日本语代表性合成材料分别通过完整流程 |
| D：持续学习体验 | P2 | 知识点标注、到期复习、学习报告与目标、搜索增强、移动端和阅读设置 | 能按薄弱点安排下一次学习，看到可靠的进步记录 |

批次A可拆为两轮：先修评分、状态、保存与控件；再接最小复核和内容模式约束。批次B先交付“续答 + 答案复盘 + 错题重练”，这三项对日常使用最直接。工期依上一份总计划评估，不与其中重复计算。

建议新增验收用例：2题答1题；空白答卷；记述待评阅；保存失败交卷；刷新恢复；未完成历史继续；完整结果直接回看；图片放大；错题筛选；收藏恢复；从错题开练；打印结果；听力中断恢复。
