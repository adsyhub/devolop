# 制作台改版：四个模块，一条制课流水线

2026-09-11。制作台从「一个页面、五个视图」改成「四个页面、四个模块」，并新增
一条一键制课流水线。

## 为什么改

制作台原来把 docs/PIPELINE.md 的八个阶段逐个摆在人面前，每一步都要人按一下。
那对「这一页到底怎么处置」是必要的，对「这 20 套卷先跑起来」是负担 —— 批量
制卷只能走 `scripts/batch_process.py` + `scripts/attest_and_publish.py` 的命令行，
界面上做不了。

分成四个页面而不是一个 SPA，是因为这四件事的停留时长完全不同：复核编辑器一坐
就是几十页，制课页开着等后台跑。同一个页面里切视图，意味着刷新一次就把另一件
事的现场也丢了。

## 四个模块

| 模块 | 路径 | 管什么 |
| --- | --- | --- |
| 制课 | `/studio`、`/studio/build` | 拖 PDF 进来，一条流水线做到可练的卷 |
| 课程库 | `/studio/library` | 来源清单与单套卷的八个阶段（原来的制作台） |
| 复核编辑器 | `/studio/editor` | 逐页对照原图核对、签署 |
| 运维 | `/studio/ops` | 跨来源的任务、内容问题、备份 |

前端文件：`studio_shell.js` 放四页共用的东西（模块导航、来源清单、阶段推导、
任务卡），其余各页一个 HTML 加一个 JS。旧的 `studio.js`（1481 行）已拆完删除。

四个页面的静态资源一律用根相对路径。`/studio/library` 比 `/studio` 深一层，
相对路径会解析成 `/studio/core.js` 而 404 —— 这是拆页面时唯一一处真正的坑。

## 制课流水线

`MAKE_PAPER` 任务，编排在 `eju_bank/make_paper.py`，由同一个 job worker 执行：

```
登记与导入 → 探测 → 渲染 → 读文本 → 读解答欄号
    → 校对·复读异常页 → 页面合同与机器校验
    → 组装与预检 → 校对·复核整卷 → 发布 → 真题详解草稿
```

它**自己**依次做完这些步，而不是排出一串子任务：worker 同一时刻只跑一个任务，
排子任务会让它们永远等在队列里。

每一步都可断点续跑（产物已在就跳过，除非勾「重跑已完成的步骤」），取消在步与步
之间和长步骤内部都有检查点。

### 闸门一个都没放松

走的是和手签卷一样的 `candidate → approve → publish`，签名用保留身份
`machine:eju-ocr-pipeline`，所以卷子带着 `reviewGrade: MACHINE_ATTESTED` 到
学习者屏幕上。判断本身搬进了 `eju_bank/attest.py`，`scripts/attest_and_publish.py`
改为从那里 import —— 命令行和页面共用一份实现，不会分叉。

- 勾「停在待复核」：任务在组装预检后停下，等人去复核编辑器逐页签。
- 真题详解一律存成 `DRAFT`。`_latest_annotations` 只取 `REVIEWED`/`WITHDRAWN`，
  所以草稿一个字都到不了学习者眼前，要人改成 REVIEWED 才会。
- 机器校验一页都没通过时，任务以 `PARTIAL_FAILED` 收尾并写明差在哪，
  而不是抛一个通用错误 —— 那是内容结论，不是流水线坏了。

## 「校对」是三件事

1. **复读异常页**（`eju_bank/proofread.py`）。首轮 OCR 用快模型，版面一复杂会丢字、
   串行、开始复述。这些页有可检测的痕迹（替换字符、长度塌缩、整段自我重复、选项
   空壳），挑出来交给更强的视觉模型重读。重读不是无条件替换：只有确实更好才顶上，
   两份读法都留在缓存里（`firstPass` / `secondPass`）。

   空白页不参与：PROBE 已经标了 `likelyBlank`，一页没有墨，OCR 读回空字符串就是
   正确答案。不排除它的话，第二个模型会讲一段「这张图是白的」，再把那段话当正文
   顶替掉诚实的空读法 —— 实测踩过。

   带思考模式的视觉模型会把推理过程和 `<|begin_of_box|>` 这类控制标记吐进正文，
   参与不了「读得更全吗」的比较，先剥掉再比。

2. **答案与选项交叉反验**。正解表给的答案必须出现在题册读到的选项里；欄号按小节
   顺序补齐的提议也要过同一道反验。这套判断本来就长在 `ocr/slot_join` 和
   `ocr/attested_contracts` 的定稿里，制课台只负责把结论显示出来。

3. **复核整卷**。文字模型逐批读题干、选项、答案，标出占位残留、截断、公式断裂、
   自相矛盾、答案越界，产出疑点清单（`work/<dir>/proofread-report.json`）。
   清单不改内容、不挡发布 —— 它是给人看的，并且会让详解跳过这些题。

### 实测

- 2005-2 综合科目：一次上传做到发布，34 题、PARTIAL、MACHINE_ATTESTED。
- 复读对机器校验的影响（2008-1 日语，13 页可疑、顶替 5 页）：
  复读前 13/53 + 3/9，复读后 13/53 + 3/9 —— **不减**。它修好的是读法，
  这一套卷里那些页本来就不是卡住组卷的那几页。
- 复读确实修得动：2002-1 数学 1 类的 4 页答案册（整段自我重复）全部被顶替；
  2002-1 综合科目 p16 由复述残篇换成完整题干。

## 模型档位

`eju_bank/model_profiles.py`。页面只能从 `config/providers.json` 里已有的档位挑，
不能自己填地址 —— 那等于让浏览器决定把原卷图发到哪台机器上。

- **视觉档位一律只走回环地址**，没有云端这条路：原页图是受版权的原卷扫描。
- **文字档位**可以走云端，但配置所有者必须显式写出取密钥的环境变量名（`apiKeyEnv`）。
- 配置里没写时用内置档位兜底，对应本机常驻的四个服务（8100/8101/8102/8103）。
- 服务没起的档位在下拉里是灰的：选不了和不知道有这回事是两件事。

## 真题详解

`eju_bank/explain.py`。官方答案是输入不是结论 —— 模型被要求解释**给定的那个
答案**为什么对；没有记录答案的题直接跳过，不让它猜。转写有疑点的题不写详解：
给一段占位文字配一篇解析，只会让错的内容看起来更可信。

**不用 JSON 传。** 解析要求模型把 `$\frac{a}{b}$` 放进 JSON 字符串，每个反斜杠都
要转义成 `\\`，实测本地模型做不到，一道带公式的题就足以让整条回答解析失败。
所以走 `###TITLE / ###POINTS / ###SOLUTION` 分段格式，对反斜杠完全免疫。

要 JSON 的地方（整卷复核的疑点清单）在 prompt 里明确禁止写公式：`\frac`、`\beta`
里的 `f`、`b` 本身是合法 JSON 转义字母，会被静默读成换页符和退格符 —— 坏掉却不报错。

## 新增的 HTTP 口

| 方法 | 路径 | 用途 |
| --- | --- | --- |
| POST | `/api/v1/admin/uploads` | 收一份原卷 PDF（裸字节流，文件名走 `X-Upload-Filename`） |
| GET | `/api/v1/admin/models` | 模型档位清单与实时可用性 |
| POST | `/api/v1/admin/papers` | 建一条 `MAKE_PAPER` 任务 |

上传那条必须在 `_body()` 之前拦下来：`_body()` 只收 2 MB 的 `application/json`，
PDF 走不进去。文件名只当推断依据，落盘名由服务端用内容哈希决定。
