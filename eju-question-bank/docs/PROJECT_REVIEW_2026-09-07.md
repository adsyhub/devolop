# 项目现状复核与后续实施计划

审查日期：2026-09-07。范围：当前目录的源码、配置、测试、文档、页面产物、原始 PDF 和 SQLite 数据。本文是本轮实际检查后的执行基线；原 `IMPLEMENTATION_PLAN.md` 保留为目标规格，其旧现状和排期不再代表当前进度。

功能专项补充：[功能完善分析与产品实施清单](FUNCTIONAL_IMPROVEMENT_PLAN.md)。后续核查新增P0评分问题：未作答题未计入汇总分母，2题仅答对1题会显示100%；另有记述待评阅显示成错误、可见控件未接通等问题，纳入首批修正。

## 1. 结论与路线

项目已经具备本地题库产品的主要骨架：PDF 制作流水线、版本化发布、基础学习界面、评分、媒体存储、数据库迁移及运维命令。后续不宜先重写框架或增加大量题目，而应先解决**内容真实性、发布门禁、作答可靠性**，再完成复核和学习闭环。

最关键的发现是：当前 2023-2 理科内容不能直接视为经过原卷校验的完整真题。抽查发现 PDF 第 41 页没有题目正文，但 `p0041-question_booklet.json` 却记录两道生物题。现有审计仍然通过，说明它只能验证部分结构，不能证明内容与来源一致。此结论只确认抽查页及其证据链存在问题，不推断全部 57 题均错误。

建议首版继续采用 Python 模块化单体、SQLite、静态 Web、本地单用户方案。本次只新增计划与审查文档、更新文档入口；未修改正式题库、来源文件和业务实现，也未运行会重建或发布数据的脚本。

## 4. 具体问题与证据

### F01 / P0：原卷与页面合同不一致，复核证据缺失

证据位置：`sources/2023令和5年第2回理科.pdf` 第 41 页（PDF 物理页，1 起算）、`work/2023-2-science/pages/p0041-question_booklet.json`、`scripts/build_2023_science.py`、`scripts/clip_all_figures_2023.py`。

直接渲染 PDF 第 41 页，正文为空，仅有页眉页脚；对应 JSON 却有 `bio-q-01`、`bio-q-02` 两题。裁图脚本还将此页区域命名为“細胞の構造模式図”。构建脚本硬编码大量题干和选项，末尾输出“reviewed”，但未建立真实签署流程。脚本开头还删除已有 `p*.json`，直接重跑会覆盖制作成果。

整改：首先建立问题台账，对现有版本标记“内容待复核”，保留历史和来源；逐页对照原卷重建错误页面，独立核对答案，不通过旧脚本直接回填。将生产脚本参数化、增加主入口和显式输出目录，默认不删除旧 revision。修订内容发布为新版本。

### F02 / P0：完整度、模式与清单状态没有形成统一门禁

证据位置：`audit.py:audit_paper`、`selection.py:validate_form_selection`、`inventory.py:inventory_status_summary`、`web/app.js:loadReviewStudio`。

- 当前 57 题卷在内存里仅改成 `COMPLETE`，不添加复核信息，审计依然 passed。完整度主要以题量阈值判断，缺少预期 form、页码、题号、答案、材料与签署的联合核验。
- 对 `PARTIAL` 且只开放 PRACTICE 的卷调用 MOCK 选科校验，选择物理和化学仍被接受；`create_session` 没有进一步校验该卷 `availableModes`。
- 清单按 PUBLISHED 计数，前端将此数显示为“已发布完整卷”。阻塞数只看 `pipelineStatus` 字符串，不看 `blockingIssues`，导致现有 5 项缺资料的 RECEIVED 条目不计入阻塞。

整改：建立 `contentKind`（真实来源/合成 fixture）、`completeness`、`reviewState`、`availableModes` 的明确关系；真实 COMPLETE 必须满足每套来源的已复核结构清单。发布状态从成功发布记录同步，完整验收率与发布率分别计算。

### F03 / P0：保存失败后仍可交卷；批量保存不原子

证据位置：`web/app.js:flushAutoSave/submitExam/startExamSession`、`db.py:record_responses_batch/record_response/submit_session`。

- `flushAutoSave` 捕获异常后正常返回，`submitExam` 随后继续交卷，可能锁定漏答结果。
- 保存过程中继续输入，旧请求成功后直接清除全局 dirty 标志，可能把更新后的未保存输入显示成“已保存”。
- 新建会话未完整重置旧 dirty/timer 状态，存在跨会话保存竞态，需要浏览器复现验证。
- 批量接口逐项调用会提交事务的单条保存：临时库中提交“合法第一项 + 非法第二项”，接口报错后第一项已经入库。
- 提交前读取状态、答案与开启事务不是同一原子过程；并发答题/提交的竞态尚缺测试，需进一步验证。

整改：前端建立与 session 绑定的待保存队列、请求序号与已确认版本；只在确认成功后移除对应更新。交卷必须先确认 flush 成功，失败时保留输入并阻止交卷。后端整批预校验并事务提交；提交与保存采用明确并发控制。

### F04 / P0：备份存在，但缺少一致性与恢复验收

证据位置：`ops.py:create_backup/verify_backup/restore_backup`、`tests/test_ops.py`。

备份直接把正在使用的 SQLite 文件压入 ZIP，没有使用 SQLite backup API；并发写入或 WAL 场景的一致性未保证。verify 主要检查 ZIP CRC，缺少数据库也会给 `valid=true`：本次对仅含 `unrelated.txt` 的 ZIP 已复现。restore 直接解包，未先执行数据库、版本和媒体引用检查。

整改：用数据库快照制作备份；清单登记必需文件、schema 版本及每个文件哈希；校验必需文件、数据库完整性与外键、媒体引用；在临时目录恢复验证成功后再交付目标目录。增加大小/数量限制，失败保留原目标。

### F05 / P0（启用远程访问前）：边界支持尚未完整落实

证据位置：`server.py:serve/_security_check/_body`、`security.py`、`publish.py`、`db.py:publish`。

- `serve` 未强制非 loopback 绑定必须配置 token 和 allowlist；远程开关开启时，未传 allowlist 的任意 Host/Origin 会被接受，已在函数级复现。
- 管理 token 未配置时允许访问；前端 API helper 没有管理 token 输入/携带流程。默认本地和远程模式的策略需要分开落实。
- 渠道权限只在 `publish_file` 外层检查；临时库直接调用 `Database.publish` 可把 PRIVATE_STUDY 内容写为 PUBLIC。属于内部入口约束缺口，不等于当前存在公开 HTTP 发布接口。
- 媒体按资产 ID 取文件，未通过已发布版本引用/停用状态判断交付；异常响应普遍直接返回 `str(exc)`。
- `_body` 未拒绝负 Content-Length；分页、批量体等缺少完整类型/范围限制。

整改：发布门禁下沉到统一服务入口；远程启用必须明确通过配置验证；Host/Origin 精确匹配；媒体绑定有效发布引用；错误对用户脱敏、服务端记录 request ID；补齐输入验证与请求超时。本项只分析实现约束，不重新评估来源的法律权利。

### F06 / P1：所谓复核台目前只是清单展示

证据位置：`web/app.js:loadReviewStudio`、`server.py`、`migrations.py`。

缺少原页与结构并排查看、bbox 高亮、字段编辑、diff、保存草稿、签署/撤回、答案证据复核。数据库已有相关空表，应接通流程。最小复核能力需要提前到内容修复阶段，而不是等待高级编辑器全部完成。

### F07 / P1：学习恢复、顺序和版本一致性尚不完整

证据位置：`web/app.js:startExamSession/loadHistory/renderReviewList`、`db.py:get_session/get_history`、`assemble.py`。

- 前端没有刷新后恢复 session 的流程，历史页只查看结果，不能继续未交卷会话。
- session 服务端绑定版本，但前端创建 session 后另取“最新 paper”；若期间发布新版本，展示题卷与会话题卷可能不同。session 查询也没有提供足够的卷版本定位字段。
- 历史结果展示依赖全局 `activePaper/activeQuestions`，需独立加载历史绑定版本，避免标题或题目上下文错位。
- 生物产物出现問2 排在問1之前；生成脚本 `readingOrder=qnum % 2 + 1`、assembler 按该字段排序可解释此结果。form/group 使用字符串排序也不应代替原卷顺序。
- 错题页已有“掌握”操作，尚无基于错题集合的新练习；笔记 API 已有，界面编辑/恢复未形成流程；收藏开始会话时被清空为本地空集合。

### F08 / P1：媒体、音频和离线体验只接通一部分

证据位置：`assets.py/audio.py/audit.py/server.py/web/`。

媒体文件可存储和交付，但正式库 `assets/paper_assets` 为空。audit 的图形检查集中于材料/题干顶层，未完整检查选项及嵌套节点，也没有验证 asset ID 对应文件是否存在且哈希正确。文件存在也不能证明裁剪内容正确，见 F01。

音频目前有 probe、cue 校验、Range 能力，尚无完整导入/映射/播放器/服务端分区顺序控制；CSS 音频样式不等于功能实现。日本语清单缺音频与答案，应独立列为内容依赖。

数学排版通过 CDN 加载 KaTeX；断网时降级为 LaTeX 原文，与本地离线目标不一致。doctor 的 Python 最低版本写为 3.10，而包元数据要求 3.11；音频依赖也需按实际选用后端形成清晰安装入口。

### F09 / P1：OCR 缓存、schema 与运行时验证不充分

证据位置：`ocr/pipeline.py`、`page_contract.py`、`schemas/`、`db.py:publish`。

OCR 按已有文件名复用缓存，未将来源/图片哈希、prompt、模型 revision、参数作为缓存身份；输出强制写 schemaVersion=1。coverage 只比较两个计数，没有区域集合对账。schema 虽已存在，但嵌套结构仍粗略，也未成为所有入口的统一校验依据。`syllabusId` 与 `syllabusVersion` 的写入字段不一致。

整改：制作任务保存输入摘要、模型与 prompt 版本、逐页尝试及错误；缓存身份变化必须失效；失败页可单独重试。统一版本字段与 JSON 合同验证，旧格式显式迁移。地区/年份考试规则变更另安排官方资料复核，本次不把旧文档规则当作已重新验证。

### F10 / P1–P2：测试与发布文档不能代表真实使用验收

现有测试主要是模块与少量 API 路径；未找到浏览器 E2E 或 CI 配置。API fixture 使用固定端口和 sleep 等待，缺少服务关闭机制。真实 PDF 测试能检查页数、旋转、渲染，但不能验证题文和答案一致。

原计划多处仍把已经实现的迁移/媒体/历史写成“完全缺失”；README 的命令展示偏 Windows，部分脚本硬编码 `/workspace/...`。需将“目标规格”“当前验收状态”“操作手册”分开维护，完成干净环境安装、跨目录启动、升级、恢复演练。

## 6. 分阶段推进与验收门

### 阶段 A：可信基线与止损（约 1–2 周）

执行 R01、R02、R04，并开始 R03；限制远程启用，明确当前版本待复核状态。

交付：差异台账、完整度模型、可靠保存与交卷、最小复核工作页。验收门：来源不符不能静默通过；PARTIAL 不可模考；保存失败绝不交卷。未满足前，不批量导入新的真实卷。

### 阶段 B：可信内容生产（约 2–3 周，人工核对另计）

完成 R03、R05、R06、R07，推进 R08、R11；开始故障和浏览器测试。

## 8. 必补测试与验收清单

- **内容与发布**：空白页被填写题目应由复核/证据门阻止验收；缺预期题号/答案/材料/选项图失败；签署后修改内容失效；无权限的底层发布被拒绝。
- **状态与模式**：无 blockingIssues 的发布成功才更新相应状态；阻塞数包含 RECEIVED+MISSING_*；完整率和发布率分开；不支持的模式在 API 端拒绝。
- **保存与会话**：连续快速修改、慢请求返回乱序、断网重试、批量末项非法、保存中切换会话、到时提交、并发重复提交、刷新恢复、旧版本恢复。
- **恢复与迁移**：真实带结果的旧库迁移、重复迁移、失败回滚；写入中备份；缺文件/坏库/损坏媒体恢复失败；恢复后图形和历史可打开。
- **交付与安全**：非法 body/分页参数；负长度与过大请求；Host/Origin/token 组合；媒体未发布/停用/缺失；错误不返回系统路径；答案不出现在交卷前 learner payload。
- **浏览器**：全科合成题、数学公式离线显示、图片缩放、音频 seek 与失败提示、键盘操作、移动窄屏、历史直接回看。

复核测试应使用人工标注的小型基准集，不能仅让脚本生成数据后再断言脚本自己的题量。CI 使用合成材料；含真实来源的完整核对在本地受控流程执行。
