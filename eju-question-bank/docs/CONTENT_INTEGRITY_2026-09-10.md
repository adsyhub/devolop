# 题库内容真实性调查与修正（2026-09-10）

起因：使用者报告「题目全是图片显示，完全没法用」，并怀疑是当天的前端重构造成的。

## 1. 结论先行

**不是前端造成的。** 三条独立证据：

1. `renderAst` 逻辑逐字未变——与重构前备份对比，差异全是换行与缩进重排。
2. 把备份的旧 `web/` 目录临时装回，用**同一个数据库**渲染同一道题，可见文本与新前端一字不差：同一张整页图、同一句模板题干、同样的「選択肢 (1)(2)(3)(4)」。
3. 内容是 `scripts/build_and_publish_all.py` 写进库的。该文件修改时间 11:35，数据库最后一批发布 11:36。

## 2. 真正的问题

### 2.1 题面是模板，不是 OCR 文本

当前 217 套卷中，只有 4 套含真实题目内容：

| 卷 | 状态 |
|---|---|
| `eju-2023-2-science` | 2026-09-04 发布，真实内容 |
| `eju-2023-1/2-japanese`、`eju-2024-1-japanese` | 有真实 OCR 读解原文与选项（这 3 个来源有 `ocr_cache/`） |
| 其余 213 套 | 题干为模板、选项为字面 `選択肢 (n)`、材料为整页扫描图 |

原因：脚本只在 `ocr_cache/` 存在时读真实文本（[L258-264](../scripts/build_and_publish_all.py#L258-L264)），而 216 个工作目录里当时只有 3 个有该目录，其余全部落回硬编码模板。

### 2.2 所有正确答案都是算出来的（更严重）

`grep -c "ANSWER_KEY" scripts/build_and_publish_all.py` 结果为 **0**——脚本从未读取答案册。原先的答案来源：

| 位置 | 原代码 |
|---|---|
| L64 物理 | `"optionKey": str((q_num % 5) + 1)` |
| L95 化学 | `"optionKey": str(((q_num + 1) % 6) + 1)` |
| L126 生物 | `"optionKey": str(((q_num + 2) % 6) + 1)` |
| L161 数学 | `tokens = {slot: str((g_idx * 2 + q_sub) % 9 + 1) ...}` |
| L206 総合 | `"optionKey": str((q_num % 4) + 1)` |
| L847 読解 | `"optionKey": str((q_num % 4) + 1)` |
| L910 聴解 | `"optionKey": str(((q_num + 2) % 4) + 1)` |

后果：这 213 套卷产生的正确率、错题本与全部学习统计都无意义，即使那 3 套有真实 OCR 选项的日本語卷也一样。

发布路径同时绕过了复核流程（直接 `db.publish()`，[L1066](../scripts/build_and_publish_all.py#L1066)），所以 `paper_reviews` 表 0 条、`page_revisions` 仅 1 条——213 套卷没有任何人签署过。

`eju_bank/audit.py` 本来要求每道客观题有有效 `correctAnswer`（L173-190），编造答案正是为了通过这道闸。

### 2.3 硬约束：150 个来源没有答案册

216 个来源中只有 65 个声明并渲染了 `ANSWER_KEY`。**其余 150 个无论如何 OCR 都无法得到可验证答案。**

## 3. 本轮修正

### 3.1 发布脚本改为 fail-closed

- 删除全部 7 处凭空计算的 `correctAnswer`。
- 新增校验闸门 `enforce_verified()`：现在是**唯一**给 `correctAnswer` 赋值的地方，来源只能是答案册。
- 题面为占位（选项匹配 `選択肢 (n)`，或题干含模板标记）的题一律丢弃。
- 查不到可验证答案的客观题一律丢弃；整卷无题可留则不发布。
- 逃生开关 `--allow-unverified` 默认关闭，开启时打印显著警告。

实测：`2002-1-japanese` 由 53 题（全假）变为保留 17 题，丢弃 36 题（无可验证答案 5，题面为占位 31）。

### 3.2 新增真实 OCR 工具链

| 文件 | 作用 |
|---|---|
| `scripts/ocr_extract_all.py` | 调用运行中的 GLM-OCR 服务（`127.0.0.1:8102`，OpenAI 兼容）逐页识别，可断点续跑。不在进程内再加载一份模型。 |
| `eju_bank/ocr/answer_key.py` | 解析正解表的「問／答」配对行 → `{answerRef: 答案}`。行长度不符即报告不配对，绝不猜哪一列错位。 |
| `eju_bank/ocr/question_blocks.py` | 把一页 OCR 文本切成题块，支持真实存在的两种选项排版：`$\textcircled{n}$`（総合/理科）与行首 `1.`（日本語）。选项不是完整 1..N 即丢弃。 |
| `eju_bank/ocr/answer_table.py` | 解析按 HTML 识别的正解表，展开 rowspan/colspan 还原「題号→解答欄→答案」，含一问多欄的情况。表头对不齐就不采用題号。同时支持无解答欄行的形态（`問 1番…／答 3 4…`）。 |
| `eju_bank/ocr/assemble_from_ocr.py` | 用 OCR 真读出来的题组卷：题面来自原页，答案来自正解表。只组装能**证明**对得上的题。 |
| `scripts/ocr_slot_numbers.py` | 裁右边距读方框里的解答欄号——全科目通用的对接键。整页转写会丢掉它们。 |

测试：`tests/test_answer_key_parse.py`（7 项）、`tests/test_question_blocks.py`（6 项）、`tests/test_answer_table.py`（7 项）、`tests/test_assemble_from_ocr.py`（8 项），全部以真实 OCR 输出为夹具。

实测有效性：正解表单页解析出 82 条真实答案，0 条不配对；题块解析在 507 页缓存上得到 262 题真实题面。

### 3.3 答案对接的安全规则

正解表按**解答欄号**连续编号，题册按**分科内題号**（每个罗马数字大题重新起 1），两者不能直接按題号对接。

先记一条纠正：**「OCR 题数 == 分科答案数」不是有效校验。**实测证明一道题可以占多个解答欄——正解表把「A」印成 `<td colspan="2">`，它独占解答欄 6、7 两格；被删除的题也照样占号。所以数量不等是常态，不代表提取有误。

可靠的对接依据是正解表自身的表格结构。把答案册按 HTML 识别（保留 rowspan/colspan）后，「題号→解答欄→答案」可以精确还原：

| 題号 | 解答欄 | 答案 |
|---|---|---|
| 問1 | 1 | 3 |
| 問5 | 5 | 2 |
| A | 6, 7 | 2, 3 |
| B | 12, 13 | 1, 3 |

压成纯文本就丢掉了这层信息（12 个表头项对不上 13 个解答欄）。因此：

1. 答案册用表格 prompt 识别（`scripts/ocr_extract_all.py` 按角色区分 prompt）。
2. `解答欄 → 答` 的配对是权威的，始终采信。
3. 題号只在其表头行**列数与解答欄数可验证一致**时才附加；对不齐就如实记入 `problems`，不硬安。OCR 对合并单元格的 span 估计不可靠（实测大题行给出 15 列而解答欄只有 13 列），这条对齐校验是防止把答案安到错题上的关键。

### 3.4 答案册：已打通

答案册按**两种读法各取一次**（`raw_text` 为 HTML、`raw_flat` 为纯文本），在闸门里合并：纯文本铺底（它能读到落在 `<table>` 标记之外的小节标题），结构化覆盖（一问占多欄只有它能表达）。

实测每套来源合并出 **128 条已验证答案**，覆盖全部小节：

```
聴解 20 · 聴読解 20 · 読解 20 · 物理 22 · 化学 13 · 生物 11 · 総合科目 22
```

与原文逐条核对一致（聴解1番=2、読解問1=1、物理解答欄1=3 …）。正解表是整场考试共用的，所以同一回次的各来源拿到同一份答案，各取自己需要的小节。

### 3.5 题册：解答欄号是全科目通用的对接依据

EJU 题册给**每道客观题**在右边距印了一个方框，框里就是解答欄号：

```
問3  質量Mのおもりにかかる力は…                        ┌──┐
     次の①～⑤のうちから正しいものを一つ選びなさい。    │ 8│
                                                      └──┘
```

这是最可靠的键——印刷題号在每个大题里重新起 1，而正解表的嵌套表头又不总能还原。

**但整页转写会丢掉这些方框**：文档 OCR 模型把它们当图形。三种 prompt（纯文本、markdown 布局、显式要求读方框）在全页上都读不出来。改用 GLM-4.6V-Flash 全页提问可以读出（实测 問3→8、問4→9、問5→10，与原图逐个核对一致），但 9 秒/页，6463 页要 16 小时。

可行做法是**先裁右边距再识别**：方框成了图上唯一内容，GLM-OCR 读得又快又准。

| 裁切 | 结果 |
|---|---|
| 右 22% | 三页样本全部读对（3,4,5 / 6,7 / 8,9,10）· 0.5 秒/页 |
| 右 15% | 切到框，读出错 |

物理分科整段验证：9 页读出的并集恰好是 **1..22**，无缺无多。

噪声（页眉「理科一11」、页脚页码、挤进边距的选项号）用一条规则排除：**解答欄号在分科内严格连续**，所以只接受等于「上一个 + 1」的候选。这比按几何位置找页眉更稳，而且欄号照常推进，下一页能重新同步。见 `scripts/ocr_slot_numbers.py`。

### 3.6 题册：三个科目已端到端打通

日本語各节的**印刷題号就是解答欄号**（読解 問1 → `READING:1`），这个对接可直接验证。实测 `2002-1-japanese`：

```
[OCR]  并入 20 道真题（收集 20，未对接 0，无验证答案 0，顶替模板题 20）
[GATE] 保留 21 题，丢弃 32 题（无可验证答案 5，题面为占位 27）
✓ 2002-1 EJU JAPANESE · 21 题 · 通过审计
```

产出的 20 道题带真实读解原文、真实选项和正解表验证的答案：

| 題号 | answerRef | 答案 | 题干开头 |
|---|---|---|---|
| 問1 | READING:1 | 1 | 次の文章の内容と合っているものはどれですか。 |
| 問2 | READING:2 | 3 | 次の文章は新聞のインタビュー記事です。 |
| 問3 | READING:3 | 4 | 次の文章の（A）に入るものとして… |

`answerRef` 撞号时以 OCR 题为准（题面直接来自原页、答案来自正解表），模板题让位。

其他科目按同样的路径打通，各自的对接依据不同：

| 科目 | 对接依据 |
|---|---|
| 日本語 読解 | 印刷題号 == 解答欄号 |
| 理科（物理・化学・生物） | 右边距方框号 |
| 総合科目 | 右边距方框号 |

### 3.7 正解表有两种版式，都要支持

2009 年是分界线。**2008 年及以前是行式**：題号横排一行，答案横排一行。**2009 年起是列式**：一行一题，「問 / 解答番号 / 正解」各占一列，明确得多。

```
2008 及以前              2009 起
問 1番 2番 3番 …         問   | 解答番号 | 正解
答 2   4   4  …          Ⅰ    |    1     |  2
                         XⅠ 問1 |   11    |  3
```

早期只支持行式，导致 2009 年后的 28 个回次答案全为 0。补上列式后，这些回次的答案恢复。

沿途修掉四个据实发现的问题：

- **一页多小节会互相覆盖。**一页常连排 読解 → 聴読解 → 聴解，各自欄号都从 1 起。最初只取第一个表头和第一个小节名，后面小节的行被算到前一节，**答案会被安到别的科目上**。改为按小节分块，并加了回归测试。
- **小节标题带英文注释。**`物理 Physics`、`生物 Biology`、`〈総合科目〉 Japan and the World`。日文名在前且是权威标识，按最长前缀匹配。
- **标题印在表格之外。**部分页的小节名不在 `<table>` 里，结构化捕获无从归属。用同一页纯文本捕获里的标题兜底。
- **OCR 输出的 HTML 缺 `<tr>`。**续行只给一串 `<td>` 就 `</tr>`。浏览器会隐式开行，解析器也要这样，否则整行丢失。

两处按小节类型分别定优先级：題号即欄号的小节（日本語）以題号为准，方框号兜底；題号按大题重起的小节（理科/総合）反过来。把优先级搞反过一次，日本語从 20 掉到 10——已修正并加了回归测试。

另外三个据实修正：

- **同一回次共享答案册。**正解表是整场考试共用的一份文件。150 个没有答案册的来源里，很多其实能用同回次其他科目来源的答案册（各科只取自己那几节，不会串）。総合科目由此从 0 到 10。
- **`form` 必须过滤小节。**一本理科题册里物理/化学/生物是三个 form。最初 `build_questions` 没按 form 过滤，把物理题同时返回给了化学和生物——验证时抓到，已加显式的 `FORM_SECTIONS` 表和回归测试。
- **OCR 形近字容错。**实测把「解答欄」读成「解答桐」、「問」读成「间」。这类行由标签开头 + 后面一串数字唯一确定，所以允许一两字偏差。修正后 2002-2 物理从 0 个欄号变为完整的 1..22。
