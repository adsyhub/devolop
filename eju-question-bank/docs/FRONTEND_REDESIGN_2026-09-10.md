# EJU 题库前端重构方案：层级设计

**日期**：2026-09-10
**改动范围**：`eju_bank/web/` 全部前端文件；`eju_bank/server.py` 的静态路由段（`_static`，第 309 行）。
**参照系**：`../dictation/src/web/`（学习者前台）、`../dictation/src/studio_web/` 与 `../dictation/src/review_web/`（制作后台）。
**明确不改**：任何 `/api/v1/*` 契约、数据库 schema、评分口径、审核签署规则、授权门禁。本方案只重排界面层级与视觉，不动一条业务规则。

---

## 1. 现状诊断

### 1.1 一层九 tab，三种角色挤在同一条导航

`eju_bank/web/index.html:22-30` 用九个平级按钮承载整个产品：

| 顶栏 tab | 实际归属 | 问题 |
|---|---|---|
| 试卷库 | 学习流程·起点 | — |
| 答题工作区 | 学习流程·中间态 | 以 `disabled` 暴露状态机 |
| 作答复盘 | 学习流程·终点 | 同上 |
| 找题、收藏与笔记 | 一半练习入口、一半个人资产 | 两件事塞进一个 tab |
| 错题本 | 个人资产 | — |
| 练习记录 | 个人资产 | — |
| 学习统计 | 个人资产 | — |
| 资料与数据管理 | 制作者后台 | 与学习 tab 并排 |
| 内容复核台 | 制作者后台 | 同上 |

三个后果：

- **流程被压平。**「选卷 → 作答 → 复盘」是有前后顺序的路径，却表示成三个可点的平级 tab，靠 `disabled` 属性暗示顺序（`index.html:23-24`）。学习者看到两个灰按钮，不知道要做什么才能点亮它们。
- **角色被混淆。**一个只想刷题的人，导航栏里永远有「资料与数据管理」和「内容复核台」。访问令牌输入框还挂在全局 header 上（`index.html:17-20`），对学习者是纯噪音，对制作者是随手可点的危险入口。
- **个人资产被切成四份。**错题、收藏、记录、统计本是同一个「我的」，现在要在四个 tab 间来回点，每个 tab 都要重新理解一次布局。

### 1.2 没有路由

`switchTab()`（`app.js:271-287`）只切 CSS class，不动地址栏。后果：

- 刷新永远回到试卷库；
- 浏览器后退键直接跳出应用；
- 错题本里的一道题无法生成链接；
- 无法从外部直达「某套卷的某种练法」。

对照 dictation：`exam.js:2169-2216` 定义了 `#/level/<等级>[/papers|/topics]` 与 `#/exam/<slug>?mode=review&scope=wrong`，个人中心的错题本因此能直接链进某套卷的错题重练。源码注释写明了这条设计意图：

> The personal centre's 真题错题本 links straight into a paper's wrong-answer drill, so a learner who spots a weak paper in 我的 does not have to find it again by hand here.

### 1.3 密度失控的三处

- **工作区控制条**（`index.html:128`）：一行塞进 2 个 select、2 个 button、1 个 range、1 个 status——源码里就是一整行写死的，没有分组、没有折叠。
- **资料与数据管理**（`index.html:334-345`）：7 个 `<details>`，每个内部是裸 `<form>`。`import-inventory`、`explanation-qv`、`audio-review-asset`（要求 64 位十六进制）这类必须手工粘贴 ID 的输入框直接暴露，没有选择器、没有校验提示。
- **内容复核台**（`index.html:257-333`）：三大段（逐页复核 / 结构核对 / 清单表）叠在一屏，20 多个可交互控件。它们之间有严格的先后依赖——先逐页签署 → 再签署来源结构 → 再组装 → 再签署整卷 → 才能发布——但界面上没有任何元素表达这个顺序。

### 1.4 视觉系统没有身份

`styles.css:1-15` 的 token 是 Tailwind 默认 slate/blue 调色板的直接搬运（`#2563eb` / `#f8fafc` / `#e2e8f0`）。没有品牌色，没有科目识别色，没有工作区区分色。整个应用只有一种蓝，所有卡片长得一样，无法在一屏里靠颜色分辨「这是日本語还是理科」「这是学习还是管理」。

### 1.5 代码组织

四个脚本全局加载（`index.html:365-368`）：`app.js`（1492 行）+ `learning.js` + `review.js` + `workflows.js`。一个只想做题的学习者，浏览器里同样载入了全套复核签署逻辑。

## 2. 参照系：dictation 的层级模型

### 2.1 物理分层：不同角色 = 不同应用

dictation 不把角色做成同一页面的 tab，而是做成不同的应用、不同的服务进程：

```
src/web/          学习者前台     serve_course.py
src/studio_web/   课程制作工作台  studio_server.py
src/review_web/   人工审听验收台  review_server.py
```

学习者前台内部再按工作区拆成独立 HTML：

```
home.html      →  /           入口，选工作区
index.html     →  /listening  精听工作区
exam.html      →  /exams      真题工作区
lexicon.html   →  /lexicon    词汇语法工作区
me.html        →  /me         我的（跨工作区资产）
```

映射表在 `serve_course.py:62-68`，附带一条注释说明理由：

> Stable product routes. The address bar is part of the product: a learner who bookmarks a workspace should get a path naming that workspace, not the .html file that happens to implement it today. The old file names keep working, so no existing link or bookmark breaks.

### 2.2 视图分层：以真题工作区为例

```
L0  /                    home.html         选学习模式（3 张 board-card）
L1  /exams               view-home         工作区首页
L2   └ #level-switch     category-switch   等级分类 N1 / N2 / N3
L3   └ #study-mode-grid  study-mode-card   练法：整套计时 / 专题练习
L4  #/level/N2/papers    view-papers       该等级的卷子列表
    #/level/N2/topics    view-topics       该等级的题型列表 → view-parts 细分
L5                       view-setup        练习方式 + 范围 + 开始
L6  #/exam/<slug>        view-session      作答（叶子）
L7                       view-report       成绩报告
```

每层是一个 `<section class="exam-view">`，同一时刻只有一个不 `hidden`。

### 2.3 五条可迁移的原则

**（一）角色分离优先于功能分组。**
`home.html:47`：「三种学习模式是同级但相互独立的工作区。"我的"是跨模式资产，不伪装成第四种练法。」
`exam.html:36-37`：「精听和真题是独立工作区，不再作为同一顶栏里的相邻 Tab。跨模式切换先返回入口页，避免练习状态和统计口径被误认为共享。」

**（二）每一层都自我说明。**
每个视图有 hero：eyebrow（你在第几层）+ h1（这层是什么）+ copy（这层该怎么选）。分类层统一用 `category-switch`，练法层统一用 `study-mode-card`（图标 + 标题 + 一句话 + 实时统计 + 「选一套卷 →」）。`exam.html:96-98` 注释写明这是刻意的复用：「与精听板块的视频/音频分类同一套样式：两个板块的第二层分类长得一样，学习者不用学两遍。」

**（三）每层有且只有一个返回。**
`<button class="quiet-button back-link">← 返回等级</button>`（`exam.html:122`）。是一个明确的上一层按钮，不是面包屑。

**（四）深层里的横向跳转用浮层，不弹回上层。**
`index.html:29-31`：「练习中切换课程。展开一列课程压在按钮下面，不把人踢回上一级——正在练的这一句还在原处。整份课程库仍然一键可达（菜单底部）。」

**（五）地址栏是产品的一部分。**
路由不只用于刷新恢复，还是跨工作区深链的手段：`me#/mistakes/exam` 的一道错题直接链到 `exams#/exam/<slug>?mode=review&scope=wrong`。

## 3. EJU 新层级方案

### 3.1 总览

```
L0  /                        入口：选工作区
    │
    ├─ L1  /practice         練習工作区（学习者）
    │      ├─ L2  科目分类     日本語 / 理科 / 総合科目 / 数学
    │      ├─ L3  练法        整卷模考 / 单科精练 / 专项组题
    │      ├─ L4  对象        年度回次列表 · 单科分卷列表 · 组题检索器
    │      ├─ L5  setup       选科 + 模式 + 时长确认
    │      ├─ L6  session     作答（叶子）
    │      └─ L7  report      成绩与逐题复盘
    │
    ├─ L1  /me               我的（跨科目学习资产）
    │      └─ 错题集 / 收藏笔记 / 练习记录 / 学习分析
    │
    └─ L1  /studio           制作台（制作者，独立入口、独立令牌）
           ├─ 来源列表（每行显示卡在哪个阶段）
           ├─ 单来源流水线（9 个阶段，按依赖顺序解锁）
           └─ 运维（备份 / doctor / 内容问题 / 解析翻译 / 评阅标准）
```

九个平级 tab → 三个工作区，每个工作区内部有明确的深度。

### 3.2 三个工作区的边界

| 工作区 | 谁用 | 进度口径 | 需要令牌 |
|---|---|---|---|
| `/practice` | 学习者 | 单次会话 | 否 |
| `/me` | 学习者 | 跨会话、跨科目累计 | 否 |
| `/studio` | 制作者/复核者 | 来源流水线阶段 | **是** |

**访问令牌只出现在 `/studio`。** 现在挂在全局 header 的 `<details class="access-settings">`（`index.html:17-20`）整块移进制作台顶栏。学习者从此看不到它。

### 3.3 L0 · 入口页 `home.html`

对应 dictation 的 `home.html`。EJU 只有一种"练法家族"，所以入口不是三张对等的练习卡，而是**一张主卡 + 一张资产卡 + 一条克制的制作台入口**。

│                        官方等化分数。                           │
│                                                                │

要点：
- 「继续上次练习」（现在藏在 `index.html:41` 试卷库标题下方的 `#btn-continue`）升到入口页主卡，是学习者最高频的动作。
- 制作台是一条横幅，不是一张对等的卡——它不是"第三种学习路径"。
- 免责声明（现在只出现在结果页 `index.html:167`）提到入口页说一次，结果页保留。

**为什么第 2 层是科目而不是年度。** 学习者的备考身份按科目组固定（理科生 / 文科生），年度是卷子的属性。这与 dictation 用 JLPT 等级做第 2 层同构——等级是身份，年份是属性。年度回次下沉到 L4 的筛选与排序。

**三张练法卡对应现有 API，不需要新接口：**

| 练法 | 接口 | 参数 |
|---|---|---|
| 整卷模考 | `POST /api/v1/sessions` | `paperId` + `selectedForms` + `mode=MOCK` |
| 单科精练 | `POST /api/v1/sessions` | `paperId` + 单个 `selectedForms` + `mode=PRACTICE` |
| 专项组题 | `POST /api/v1/practice` | `questionIds` + `randomOrder` |

### 3.5 L4 · 三种对象列表

**整卷模考 → 年度回次列表**（`view-papers`，替换现有 `#paper-list`）

每张卡显示：年度回次 · 科目 · 出题语言 · 题量 · 预计时长 · 复核状态 · 上次练习成绩。现在的 `paper-grid` 只有标题和三个下拉筛选，卡上缺的这几项正是 `docs/FUNCTIONAL_IMPROVEMENT_PLAN.md` 3.1 节列的第 1 条要求。

```
┌──────────────────────────────────────────────┐
│ 青▌2024 年 第 1 回 · 理科              日本語 │
│    物理 20 · 化学 20 · 生物 20 题             │
│    80 分钟 · 完整整套卷 · ✓ 已复核            │
│    上次：2026-08-30 · 客观正确率 68%          │
│                              开始 →           │
└──────────────────────────────────────────────┘
```

复核状态用 `paper-badge` 显式表达四种：`✓ 已复核` / `◷ 内容待复核` / `◐ 部分练习卷` / `⚠ 缺少音频`。现在 2023 理科的"待复核暂停练习"状态在界面上没有专门的呈现方式。

**单科精练 → 分科列表**：按 `FORM_SPECS`（`eju_bank/constants.py:146-168`）列出该科目下的全部 form，显示各自跨卷可练题量。

**专项组题 → 检索器**：现有 `#tab-collections`（`index.html:186-206`）整块搬到这里。它现在被错误地和「收藏与笔记」合并成一个 tab——检索组题是练习入口，收藏笔记是个人资产，属于两个工作区。

### 3.6 L5 · setup 视图（不再是模态框）

## 7. 服务端需要的改动

### 7.1 产品路由

`_static()`（`eju_bank/server.py:309-311`）现在只做精确文件匹配：

```python
raw = "index.html" if request_path in {"", "/"} else request_path.lstrip("/")
```

`/practice` 会 404。照 dictation 的 `PRODUCT_ROUTES`（`serve_course.py:62-68`）加一张映射表：

```python
PRODUCT_ROUTES = {
    "/": "/home.html",
    "/practice": "/practice.html",
    "/me": "/me.html",
    "/studio": "/studio.html",
}
```

在 `_static` 开头查表，查不到再走现有逻辑。旧的 `/index.html` 保留可访问，任何已存在的书签不断。这是本方案对服务端的**唯一必需改动**，约 4 行。

### 7.2 CSP

EJU 的 `index.html` 没有 CSP meta，dictation 四个页面都有。EJU 全部资源本地（KaTeX 已 vendor 化），可以给最严的一条：

```
default-src 'self'; script-src 'self'; style-src 'self'; img-src 'self' data:;
media-src 'self' blob:; connect-src 'self'; object-src 'none';
base-uri 'none'; form-action 'self'
```

### 与方案不同的五处

**一 · 「探测与渲染」是可选阶段，不是硬门槛。**
方案把阶段 ③ 当作 ④ 的前置。实现时发现复核工作台的 `read_page` 直接打开原 PDF 并按需出图，
不依赖 RENDER 任务产物——没跑过 RENDER 也能逐页核对。硬锁住会拦住本来做得成的事，
所以阶段 ③ 标为可选（轨上显示 ◇，可点、不挡路），`current` 的推进跳过它。

**二 · 导入抽成独立视图。**
方案把导入放进某套来源的阶段 ②。但导入正是来源的诞生方式：第一次导入之前根本没有来源可点进去。
现在导入是 `#/import` 一个独立视图，来源列表和阶段 ② 都链到它——一份表单、两个入口，不重复 ID。

**三 · 复核人上升为贯穿流水线的「签署身份」。**
方案把复核人放在阶段 ⑦。实际上阶段 ⑤ 签署结构和阶段 ⑦ 签署整卷都要记录同一个人。
现在它固定在阶段内容区顶部，不属于任何单个阶段。

**四 · 预检失败不锁阶段 ⑥。**
方案说预检报错就锁住后续阶段。但阶段 ⑥ 的职责就是跑组装、把问题报出来——锁住它等于让人
永远看不到报告。现在预检问题显示在阶段 ⑥ 面板内（含改用「仅已签署范围」的提示），
只有真实的后端前置条件（结构未签署、整卷未签署）才锁。

**五 · 退出作答改为两个明确动作。**
原实现是一个 `prompt()` 让人输入 1/2/3 在「保存退出 / 暂停退出 / 放弃」间选。
现在顶栏是「← 保存并退出」，放弃是作答区底部一个独立的危险动作，暂停是 `#btn-pause`。
